# 英语基准库长期任务验收协议

本任务持续推进至必需范围的资料、标准和验证证据全部成立。范围为现有16个水平及4个并列备考方向，先深做初高中，人教版为主干、外研和译林为对照，商业出题、内部参考与训练用途分别验收。所有数量目标均为采样计划，不能单独证明难度有效。

## 自动执行与交接

2026-10-13用户授权恢复，并明确当前优先[24小时初高中首版任务](FirstRelease/README.md)。首版以年级取材，教材版本/进度只作元数据；不要求精确学期/教材对齐作为取材准入。首版规格/锚题/原创生成及作者解题审核先交付，不等待本协议全量门槛；首版完成不关闭未满足的M1—M7，也不代替商用、目标学生或产品细档标定。后续调度优先该交付，减少与其无关的来源扩展、事实旁查和重复快照。

2026-10-12 已建立当前聊天的连续目标，每小时自动续办任务 `lingotrip` 提供交接保障。按用户随后明确要求，当前可推进工作持续执行，阶段提交后继续下一项，不以等待小时调度替代当前工作。每次从 Git 状态、README、Registry、最新 Studies 记录恢复，优先解决阻碍标准成立的缺口。调度的实际执行以应用状态为准。

每次必须产出有证据的增量或具体失败记录：核实来源、取得材料、核读正文、修正标注、完成结构化、核权或校验。连续三批同一入口没有新证据时，记录尝试和失败，切换官方替代来源或推进其他缺口，不反复下载同一文件。访问失败不能升级成内容已收集。

完成一个已验证的逻辑变更后聚焦提交；原始受限材料留在研究缓存，凭证不入库。阶段通过、重要更正、需用户处理的依赖和最终完成时通知；重复状态保持安静。授权或真人验证暂不可取得时，推进其余独立工作，保留未通过门槛。

## 阶段检查

| 门槛 | 通过条件 | 必需证据 | 重开条件 |
| --- | --- | --- | --- |
| M1 来源与版本 | 核心来源的机构、版本、发布时间、取得方式明确；当前课标、教材和考试改革已核实 | 来源正文位置、版权页/审定信息、版本与实施范围；旧新版本关联 | 修订、失效、地域外推、来源身份冲突 |
| M2 教材与国内试卷 | 初高中主干及对照逐册逐单元完整，学期/地区/卷型样本按采样矩阵覆盖；全范围其他阶段也有适用材料 | 完整题组、配套答案/评分/音频、ISBN、学制/起点、年级学期选用证据及缺失理由 | 新版代替旧版、缺附件、伪真题、答案错配 |

| M4 题组合同与命题规格 | 完整阅读、完形、听力及适用产出任务可表达；每个适用范围有证据支持的规格和锚定集 | 能力、材料、问题、干扰项、评分、先修、支架、时间及正反例；规格证据链 | 多解、无法表达的题型、证据不足、同源泄漏 |
| M5 独立复核与目标学生 | 教研复核、分歧裁决和目标人群试做支持难度、用时与公平性判断 | 独立复核身份/角色、方法、首答与曝光记录、统计误差、题组相关、评分一致性 | 复核推翻、群体偏差、过拟合、样本不足 |
| M6 商用准入与模型验收 | 实际使用材料具备对应许可，隐藏集和反例检验达到预先登记的准入标准 | 用途许可与有效期、同源家族隔离、模型/规格版本、误放误拒及人工推翻记录 | 许可变化、隐藏集泄漏、模型或规格更换、误放 |

M1至M4可交错推进；单一阶段通过不能代表全库完成。M5和M6需要真实证据，不能用模型互评补齐。未采样阶段保持未成立，不由初高中结论外推。

## 覆盖单元和完成判定

20行总览只是入口。详细覆盖应以阶段/学期、教材系列/版本、学制/起点、地区、年份/改革、题组类型、能力目标、体裁、配套、权利和标定状态建矩阵。同源文章、同一试卷与改写家族去重。某维度不适用须写明理由，不能以空值或统一零计数代替。

每个必需单元列出计划样本及理由、已取得完整样本、复核范围、缺失附件、用途限制、反例及下一行动。探索阶段的10至20题组目标不直接成为校准样本量或最终验收阈值。校准与模型准入阈值须在评测前确定、说明方法和误差，未制定时相应门槛不能通过。

`Registry/milestones.json` 记录阶段状态、支持证据、未决依赖、复审角色与通过日期。记录通过必须有对应报告和支持证据；新增冲突重开，旧结论留在 Git 历史。`Registry/gaps.json` 中必需缺口只能因验收条件满足而关闭，或因用户明确取消范围转为不适用。代理不能自行缩小范围以宣布完成。

最终分别报告资料准备、可商用资产、命题标准、模型验证和目标学生验证的结果。全部适用门槛成立后才称圆满完成并停止自动任务；任何必需依赖未解决时，持续状态保持未完成，准确列出依赖，不使用“基本完成”替代。

## 复算与复审

运行 `python3 Research/GuYouJi-English-Benchmark/Tools/validate_registry.py` 检查登记结构和引用；加 `--check-cache` 校验本机缓存大小与摘要，`--check-processing` 校验OCR输出摘要；加 `--require-complete` 检查最终状态的登记前提。工具检查不证明内容正确、合法使用或教育效度，人工和实证验收报告仍为必需。

本地缓存位于被忽略的 build 目录，Git提交无法恢复原文件。后续须建立符合材料权限的持久保存/恢复方案；在恢复核验完成前M7不得通过。

材料和处理结果的活动引用使用仓库相对的build路径，不能携带原工作目录绝对路径。仓库外保存位置单独记录。恢复检查须实际从独立恢复根目录读取输入，避免因原目录仍存在而误判成功；旧快照需要路径迁移时，在恢复副本明确记录迁移，保留冻结原件和首次失败证据。当前运行时/同机依赖与真正异机恢复分别验收。

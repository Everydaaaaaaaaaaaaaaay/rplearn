# 研究资产保存与空间控制

2026-10-15用户要求推进研究时避免无用文件累积，当前[保存策略](retention-policy.json)优先于旧记录中的例行全量快照步骤。只保留最近两份独立完整快照；较早33份的清单原样保留，全部独有内容按SHA256只保存一次。旧清单中`copy_isolation`描述当时生成的布局，当前归档布局及恢复路径以[存储登记](local-snapshots.json)为准。未更改研究原件、当前缓存或无关用户文件。

33旧快照的158,133个文件条目共57,803,698,095逻辑字节，包含7,498个不同内容/2,758,212,020字节。全部内容与旧清单摘要核验后迁移；实际复核PDF、音频、JSON、文本、PNG、TSV恢复，并额外恢复一个最近两份快照都没有的旧README版本。旧目录只保留清单，`restore_research_asset.py`按快照ID/原路径恢复到新目标，拒绝覆写现有文件。全部35份清单及17.3万历史/当前完整树引用验证通过，归档仍是同机保存，不是异机灾难恢复。

备份目录`du`计量59G降至7.7G，但APFS此前已共享很多数据块，**不能声称实际释放51G**。这次测量可用空间约10G，前后观测差为-56,938,496字节；新保存了47,035,315字节的当前新增内容，也存在系统同时活动。目录逻辑计量与实际可用空间分别报告。

## 后续仅增量保存

`archive_new_research_assets.py --report <新的build报告路径>`保存登记原件/处理输出、清单和模型文件；同SHA复用同一对象，当前路径/SHA映射原子更新，文本元数据交给Git。新保存378个对象/47,035,315字节，当前6,807路径对应6,726独有内容。立即重放：新增对象0、复制字节0、新全量快照0；未变来源和归档对象复用已验证指纹，重新摘要0。文件指纹变化或登记摘要变化才重新核验，深度验证另用`validate_registry.py --check-current-preservation`。

`snapshot_research_assets.py`在创建目录之前拒绝例行全量快照。研究自动任务已经写入相同策略，保持仅初高中且ACTIVE；不因一批完成复制整库、展开全部页图或反复核未变文件。需要原图时只渲染相关页，保留必要证据与独有历史版本；不能以减少文件为由删除原始来源或未归档的独有内容。

## 恢复一个旧版本

运行`python3 -B Research/GuYouJi-English-Benchmark/Tools/restore_research_asset.py --snapshot-id <登记ID> --asset <旧清单中的相对路径> --destination <新的输出文件>`。工具验证原清单、归档索引、对象摘要与大小，恢复为独立文件。先恢复到新目录审阅，不直接覆写当前工作副本。

详细迁移、重复运行、旧版本恢复及空间测量报告在本机ignored研究缓存，摘要引用见存储登记的最新迁移事件。当前新增但尚未登记的来源仍在研究缓存，不能宣称它们已进入增量保存索引。

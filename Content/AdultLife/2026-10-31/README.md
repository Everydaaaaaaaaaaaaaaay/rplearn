# 成人生活剧情第一批 · v2

五个稳定剧情入口接入新阅读版本：墨尔本主线、纽约城市、新加坡主线、多伦多城市、奥克兰城市。伦敦搬家、Ruby 出游、Marcus 布展仍是准备稿候选，本批没有添加正式篇数、奖励类型或解锁门槛。

`directions.json` 是本版的可审阅生产源：固定引用已自审 v0.3 文稿的 SHA-256，逐场登记三幕、镜头、速度、停顿、选择结果，以及明确的双语改写和插入。不按关键词猜剧情，不在用户阅读时生成关键内容。

```sh
python3 Tools/ContentPipeline/build-adult-life-stories.py
python3 Tools/ContentPipeline/build-adult-life-stories.py --check
```

生成的五个 `App/Resources/Stories/*_v2.json` 是正式资源，保留全部 `v1` 脚本。新版投入使用后如需改变节点顺序或故事事实，应建立后续阅读版本，不在原 ID 上重排已保存的断点。

## 内涵、节奏与地方生活

| 城市 | 本篇真实分歧 | 在地内容如何参与剧情 | 节奏 |
| --- | --- | --- | --- |
| 墨尔本 | Ruby 想陪用户散步，也需要完成海洋项目申请；用户的下午不是无限的 | 收班后的咖啡馆、门外电车声；菲利普港湾重复出现的瓶盖，让申请从漂亮的“热情”变成想追问的具体问题 | 拉花玩笑开场 → 顶班与申请冲突 → 二十分钟的陪伴或离开；用磨豆机的打断和继续打字留白，不替申请写成功结局 |
| 纽约 | Marcus 误报等待时间；双方是否还能见面，要由真实剩余时间决定 | 二手唱片到货、缺价签和交班时间解释工作为何拖延；餐车、街角开门的唱片店让一小段相处有自己的声音 | 冷午饭与电话 → 明确时间 → 短走/短坐；离开线另在晚上商量，拒绝再约时不追加日期 |

| 多伦多 | 发错群的主人需要补救，来客可劳动、只陪聊、接受请客或自愿分担 | 公寓电梯、门禁、聚餐、加元订单费用进入具体行动；不以某道菜代表整座城 | 三个蛋糕的轻喜剧 → 厨房与订单两种处理 → 一首歌、一声门铃与吃饭；不给付钱者更好关系结果 |
| 奥克兰 | 社区工作台有限时，Hana 自己也有要做的东西 | 海港渡轮声、借还工具和共享台位；“只约到午饭”让十分钟帮助有真实边界 | 工具箱先回来 → 带抽屉者自己参与记录 → 带走自己的东西；之后可扶架子或坐着聊茶，不包装成维修奇迹 |

地点、人员、小型活动、班次和具体经历均为虚构创作；真实城市要素不是实时天气、营业和交通指引。故事意义由各自的选择与行动承担，不统一加一段道理。

## 画面与声音

本批复用原版已存在的手绘画面，不引入新图片。逐场引用限于实际使用的镜头；没有把原版“已提交申请”或“修好的抽屉”成果图带进尚未完成的结尾。

- Ruby：咖啡馆、交谈、填写申请、离开后的巷道；不使用提交成功图。
- Marcus：远程电话保持空场午餐画面，一点二十到达后才出现立绘；晚间消息独立切换夜景。
- Mei：用熟食中心远景承接拍照，不沿用“Mei 朝用户举起另一部手机”的原构图去冒充用户手机合照。
- Maya/Sam：厨房图含鸡蛋，生产文本也改为米饭、鸡蛋与蔬菜，并在选择前列出；点餐结尾从订单切回公寓，排除提前吃上切好蛋糕的甜点图。
- Hana/Peter：使用维修桌与解释镜头，不使用完成抽屉的成果图；工具箱在本篇开局明确归还。

旧预制录音仍绑定原角色、原节点及原文本。v2 使用现有本地 Supertonic 语音路径及相同角色选角，按场景给速度和停顿，不会播放旧台词冒充新版。本批未制作或验收一套新的预制录音库，也不将本地语音可用描述成演出声音已逐句验收。

## 数据与承接

- 目录和奖励身份不变。新阅读 ID 独立保存节点和选择；旧存档、预览断点、完成时间、奖励账本保留。
- 有旧版未完成进度时默认继续旧版；“回看对话”可进入新版，旧版仍可回来读。已经有新版进度时默认续读新版。
- 第一次完成才保存本版的 `experience.<结尾>` 证据。普通存断点不能注入该证据；重玩不覆盖第一次结果。阅读恢复剔除这组证据，只还原实际阅读 flags。
- 新版完成以原奖励 ID 结算；目录完成投影识别 v2，避免为了显示完成而覆盖已有旧版断点。
- Ruby 与 Marcus 的聊天按稳定主角身份读取本版完成证据。只承接该次相处，不伪造别的分支、录取、会面和和解；尊重既有遗忘截止时间。Maya、Mei、Hana 没有因此被新增为聊天好友。
- 英语能力与生活阶段分开，基础档不再强制每轮问句结尾；意思清楚时角色不主动纠错，用户求语言帮助才给一处表达。本批没有改动辅助教练卡片的全部展示策略。

# 游客、公共角色库与权益施工方案

状态：施工中。本文是本次实现与验收清单；未勾选的项目不代表已上线。当前仅完成下述阶段一的本地验证，尚未部署。

## 产品边界

- 游客具有服务器签发的匿名身份，可以正常登记 NPC、领取固定头像、建立关系。
- 身份状态（游客/已登录）与订阅方案（免费/Pro/Max）分别管理。剧情旅伴不占普通好友位。
- 游客 3 个普通好友位、一次性体验额度、只能在起始城市活动、每条剧情线只开放首站。
- 免费账号 5 个普通好友位、每日恢复额度；可按游戏规则旅行和继续剧情。
- Pro/Max 支持配置更多好友位、额度及高级能力。10/20 个好友位是初始试行值，不承诺无限用量。
- 先开放一个主要付费方案；兼容已存在的 Plus/Pro 订阅标识，不擅自重建 App Store 商品或改变既有购买归属。
- 未开发的专项训练、深度评估等仍为后续产品候选，不作为本次付费承诺。价格和正式配额须由成本观测决定。
- 降级或额度耗尽保留聊天、角色、记忆、收藏和剧情成果。超额好友保留，阻止继续新增；登录前检查不会扣机票或奖励。

## 公共角色生命周期

公共库保存永久 UUID、旅行者号、角色基础身份与头像绑定；每个用户的关系、记忆、聊天和经历独立。
活动先按地区、语言、参与活动的理由等检索候选，剔除身份冲突与该用户已占用的其他角色头像；
再按适配程度、多样性与重复曝光选择。合适时复用已有角色；不足时生成新角色并幂等登记。
已认识的角色重逢沿用本地关系，不覆盖记忆。未加好友及已移除角色的头像仍占用。
缺头像保留待登记请求，扩图后按原身份补齐。永久身份不因降低活跃度而删除。
记录场景候选量、复用/生成、缺口、重复曝光；活跃候选供给稳定后降低新生成比例，而非强行限制历史总人数。

## 身份与继承

匿名凭证由服务器签发，安装凭据保存在钥匙串，服务器只保存不可逆摘要。
游客权限由服务端校验；普通设备 ID 不能冒充已登录账号。领取和消费记录持久化，重启、退出或刷新不补发。
登录继承必须验证游客凭证和账号凭证，幂等认领同一游客，只能认领到一个账号。
NPC 关系、永久已见头像记录与待补图身份一并继承；已有账号的资料/资产合并采用明确规则，冲突保留数据。
客户端切换前保存待上传内容，失败可重试，不用清空本地库解决问题。

## 额度与成本

游客使用终身体验窗口；免费使用服务器每日窗口；订阅支持月度窗口与短时速率限制。
用户可见额度按聊天、语音分钟、高级操作组织；内部记忆/纠错调用记录成本，不伪装成多条用户消息扣数。
服务端原子预留、成功结算、失败释放；重试与并发不重复消费，不允许客户端提交负数或自行扩额。
记录任务、模型、输入输出 token、缓存、语音时长、失败重试与关联操作；缺价格标记成本未知，不计为零。
价格表可配置且带版本，生成按场景/档位/用户的成本分布报告，并支持按净收入与目标利润反推额度。
初始额度为可调整的试行配置；正式商业额度与长期留存结论不得以模拟测试冒充。

## 验证与发布原则

每阶段跑最小相关测试，涉及事务及认领在明确隔离的 PostgreSQL/Redis 中验证；不在生产创建测试账号或批量角色。
迁移保持向后兼容，先后端再客户端。部署前检查具体变更、迁移与回退方案；用户数据和已有订阅标识保留。
需要外部商品配置、真实成本样本或用户登录时，将具体缺口记录在此，不能声称已完成这些验收。

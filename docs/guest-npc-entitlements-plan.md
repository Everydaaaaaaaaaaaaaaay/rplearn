# 游客、公共角色库与权益施工方案

状态：代码实现和本地回归已完成，正在进行模拟器验收与发布。本文区分实现、实际验证和商业观测；未勾选项不代表已上线。

## 产品边界

- 游客具有服务器签发的匿名身份，可以正常登记 NPC、领取固定头像、建立关系。
- 身份状态（游客/已登录）与订阅方案（免费/Pro/Max）分别管理。剧情旅伴不占普通好友位。
- 游客 3 个普通好友位、一次性体验额度、只能在起始城市活动、每条剧情线只开放首站。
- 免费账号 5 个普通好友位、每日恢复额度；可按游戏规则旅行和继续剧情。
- Pro/Max 支持配置更多好友位、额度及高级能力。10/20 个好友位是初始试行值，不承诺无限用量。
- 先开放一个主要付费方案；兼容已存在的 Plus/Pro 订阅标识，不擅自重建 App Store 商品或改变既有购买归属。
- 未开发的专项训练、深度评估等仍为后续产品候选，不作为本次付费承诺。价格和正式配额须由成本观测决定。
- 降级或额度耗尽保留聊天、角色、记忆、收藏和剧情成果。超额好友保留，阻止继续新增；登录前检查不会扣机票或奖励。

## 公共角色生命周期

公共库保存永久 UUID、旅行者号、角色基础身份与头像绑定；每个用户的关系、记忆、聊天和经历独立。
活动先按地区、语言、参与活动的理由等检索候选，剔除身份冲突与该用户已占用的其他角色头像；
再按适配程度、多样性与重复曝光选择。合适时复用已有角色；不足时生成新角色并幂等登记。
已认识的角色重逢沿用本地关系，不覆盖记忆。未加好友及已移除角色的头像仍占用。
缺头像保留待登记请求，扩图后按原身份补齐。永久身份不因降低活跃度而删除。
记录场景候选量、复用/生成、缺口、重复曝光；活跃候选供给稳定后降低新生成比例，而非强行限制历史总人数。

## 身份与继承

匿名凭证由服务器签发，安装凭据保存在钥匙串，服务器只保存不可逆摘要。
游客权限由服务端校验；普通设备 ID 不能冒充已登录账号。领取和消费记录持久化，重启、退出或刷新不补发。
登录继承必须验证游客凭证和账号凭证，幂等认领同一游客，只能认领到一个账号。
NPC 关系、永久已见头像记录与待补图身份一并继承；已有账号的资料/资产合并采用明确规则，冲突保留数据。
客户端切换前保存待上传内容，失败可重试，不用清空本地库解决问题。

## 额度与成本

游客使用终身体验窗口；免费使用服务器每日窗口；订阅支持月度窗口与短时速率限制。
用户可见额度按聊天、语音分钟、高级操作组织；内部记忆/纠错调用记录成本，不伪装成多条用户消息扣数。
服务端原子预留、成功结算、失败释放；重试与并发不重复消费，不允许客户端提交负数或自行扩额。
记录任务、模型、输入输出 token、缓存、语音时长、失败重试与关联操作；缺价格标记成本未知，不计为零。
价格表可配置且带版本，生成按场景/档位/用户的成本分布报告，并支持按净收入与目标利润反推额度。
初始额度为可调整的试行配置；正式商业额度与长期留存结论不得以模拟测试冒充。

## 多模型演进（新增约束）

未来候选包括用户提到的 GLM 5.3 Flash、混元 3；具体官方型号、供应商接口与价格在接入时核验。
按业务任务路由模型，不预设全站统一替换：conversation、character_generation、memory_summary、
coach_review、grammar_explain 等分别评测并配置。每次调用记录 provider/model/configVersion/operationId，
成本与效果按同一维度对比，业务额度不绑定某个供应商的 token 单位。
当前运行适配器仍是 DeepSeek，任务路由已有独立版本与回滚；新供应商需要独立适配器、密钥、参数校验、
流式与结构化输出测试，完成后才可启用。不要用 DeepSeek 参数或价目表套算其他模型，也不要自动向未启用供应商发送用户聊天。

## 验证与发布原则

每阶段跑最小相关测试，涉及事务及认领在明确隔离的 PostgreSQL/Redis 中验证；不在生产创建测试账号或批量角色。
迁移保持向后兼容，先后端再客户端。部署前检查具体变更、迁移与回退方案；用户数据和已有订阅标识保留。
需要外部商品配置、真实成本样本或用户登录时，将具体缺口记录在此，不能声称已完成这些验收。

## 阶段二实现与边界（2026-09-06）

- PostgreSQL 用量账本按操作 UUID 去重：预留、成功结算、失败释放；同一 ID 改请求拒绝，进行中返回冲突，已成功请求重放缓存。缓存最多保留 24 小时，消费记录永久保留；过期结果不能再次免费生成。
- 游客终身、免费 UTC 自然日、付费 UTC 自然月恢复。语音每次最多预留 60 秒，按服务器经过时间结算，失联最多收取该次预留时长。AI 预留期限按路由超时/重试设置；内部辅助调用有独立上限。
- 角色生成和对话使用聊天额度；语法、词义详解和口语反馈使用高级额度；记忆、翻译、教练等辅助调用不额外显示为用户聊天扣数。对话格式修复只允许关联一次成功的原操作，避免同一轮重复扣聊天额度。
- 游客在服务端禁止买票和旅行；只允许起始城市的主线首站、城市剧情首站。客户端在扣票/扣币前给出登录入口。原调试加币入口已移除。
- 新账号继承游客资料；已完成引导的老账号保留自己的起始城市/资料。剧情奖励按故事 ID 去重，机票按来源去重，城市解锁取并集；不直接相加旧开发期余额。
- 登录前保存受系统文件保护的本地 JSON 备份；共享角色合并好友/收藏/登记状态、保留较强关系和私人备注，剧情成果取并集。其余 UUID 历史并存。备份可导出，音频文件不嵌入 JSON；它不是完整旅程恢复界面。
- 两段旅程中若不同 NPC 占用同一头像，认领事务拒绝并保留双方数据，提示改用新账号。不得为合并方便打破永久头像绑定。超过当前好友上限的历史关系保留，只限制新增。
- 游客注册新身份有终身上限，账号有每日上限；待补头像不会被该上限挡住。库增长按场景候选供给调节，历史身份不删除。库并非永远物理为空：既有剧情旅伴与导入角色可以预置，普通角色池按活动持续增长。
- 客户端“我的”和额度错误入口显示余额、周期、试行提示；先展示一个主要付费档，兼容既有 Plus/Pro 商品与已购权益。现有服务端已购好友位配置优先，不强制把历史 30 位降成 10/20 位。

## 成本观测与正式配额定标

运行 `cd Backend && pnpm usage:report`；可用 `USAGE_REPORT_SINCE` 指定起点、`AI_PRICE_BOOK` 指定价格表。
报告按档位/任务/供应商/模型/路由版本统计请求与用户的 P50/P90/P95，以及未知费用、重试次数、场景复用和缺口。
价目表来源：[DeepSeek 官方定价](https://api-docs.deepseek.com/zh-cn/quick_start/pricing)，观测时间 2026-09-06，
仅从价格表声明的生效时刻开始估算，不回填历史账单。费用为 `(未缓存输入×输入单价 + 缓存输入×缓存单价 + 输出×输出单价) / 100 万`，
当前 DeepSeek 表另按官方北京时间高低峰调整。未来供应商必须配置自己的价格/计费规则，不默认沿用该时段规则。
缺 token 或缺价格标记未知；缺缓存明细采用输入成本上界；失败/多次尝试的未知费用单独列出。此报告不是供应商账单。

正式上线定价前按真实功能流量观察至少完整日周期和付费使用分布，核对供应商账单、缓存命中、失败重试、存储与基础设施。
可用预算 = 订阅净收入 × (1 − 目标毛利率) − 单用户基础成本；按各功能实际使用占比与 P90/P95 成本倒推配额，并保留波动余量。
当前没有足够长期样本，不能声称已验证利润或留存；GLM/混元的实际接入、对比评测和商品定价仍属于后续决策。

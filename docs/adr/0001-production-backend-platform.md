# ADR 0001：生产后端平台与权威状态

- 状态：已采纳
- 日期：2026-07-26
- 决策者：LingoTrip 工程团队

## 背景

LingoTrip 当前是本地优先的 iOS 应用。账号、权益、旅行进度、虚拟经济和 AI 调用若继续由客户端直接维护，会产生以下问题：

- 无法在 iOS、Android、Web 等平台间共享一套可信状态；
- 客户端密钥和本地数据可被篡改，不能作为商业权益或虚拟经济的事实源；
- 无法统一执行订阅验证、配额、风控、审计和数据治理；
- AI 提供商、模型和提示词与具体客户端耦合，发布调整成本高；
- 日志、指标和故障定位缺少贯穿一次请求的上下文。

## 决策

### 1. 采用 TypeScript、Node.js 与 Fastify 的模块化单体

后端代码放在根目录 `Backend/`，按领域划分模块。HTTP API 与后台任务共用领域和基础设施代码，以两个独立进程运行。

早期不拆微服务。只有当模块具有独立扩缩容、隔离故障域或组织所有权的明确需求时，才通过稳定的模块接口逐步拆分。

### 2. PostgreSQL 是业务权威数据源

账号、身份、设备会话、订阅、权益、用户进度、虚拟经济、内容状态、AI 用量和审计记录都以 PostgreSQL 为事实源。

Redis 只保存可丢失或可重建的短期状态，例如分布式限流、缓存、短任务锁和撤销缓存，不保存唯一业务事实。

### 3. 客户端本地数据库是缓存与 Outbox

SwiftData 不再决定订阅权益、机票余额、城市解锁或跨设备进度。客户端可以离线读取缓存，并将允许离线产生的操作写入 Outbox；服务器通过幂等键、版本号和领域规则接受或拒绝写入。

### 4. 对外提供版本化 REST API 与 SSE

- 业务 API 使用 `/v1` 前缀；
- 普通操作使用 JSON REST；
- AI 文本流使用 Server-Sent Events；
- 每个写请求支持幂等键；
- 错误使用稳定、跨平台的机器可读错误码；
- OpenAPI 是客户端契约的可生成事实源。

未来若需要 WebSocket，只用于确有双向实时交互的功能，不替代常规同步协议。

### 5. 认证采用短期访问令牌与可轮换刷新令牌

- 访问令牌使用非对称签名 JWT，短时有效；
- 刷新令牌为高熵不透明随机值，数据库只保存摘要；
- 每次刷新都轮换令牌并检测旧令牌重放；
- 一个账号可以拥有多个可撤销设备会话；
- 密码使用 Argon2id；
- 登录身份由可扩展的身份提供商适配器管理，首批支持邮箱密码与 Sign in with Apple。

### 6. 订阅、AI 和外部身份使用提供商中立的适配器

领域层只识别统一的产品、订阅、权益、模型能力与身份，不直接暴露 Apple、Google、Stripe 或 DeepSeek 的数据结构。

首个订阅适配器是 Apple App Store，后续可以增加 Google Play 与 Web 支付。首个 AI 适配器是 DeepSeek；开发阶段所有任务路由默认使用 `deepseek-v4-flash`，但路由配置保留按任务切换提供商、模型和推理参数的能力。

### 7. 关键资产使用追加式账本和变更序列

- 虚拟货币、机票和需审计的资产变更使用追加式账本；
- 订阅通知、支付事件和 AI 计量事件保存提供商事件标识并幂等处理；
- 每个用户拥有单调递增的同步序列，变更流含删除墓碑；
- 派生余额和物化状态可以重建，不能绕过领域服务直接改写。

### 8. 使用 Drizzle 管理模式与迁移

数据库结构由类型化 Schema 和只向前迁移管理。生产环境不使用进程启动时自动修改表结构，迁移由部署流程显式执行。

### 9. 可观测性和安全默认启用

- JSON 结构化日志并统一脱敏；
- 请求 ID、用户 ID 摘要、会话 ID 和 Trace ID 贯穿调用；
- OpenTelemetry 输出指标与追踪；
- 业务审计日志与应用调试日志分离；
- 默认不记录密码、令牌、收据、AI 密钥、完整提示词和完整回复；
- 配置启动即校验，生产配置缺失时拒绝启动。

## 后果

### 正面

- iOS 与未来平台共享同一套领域规则和权威状态；
- AI 模型、订阅提供商和身份提供商可以独立替换；
- 关键资产变动可追溯、可对账、可重放；
- 单体事务能覆盖当前主要业务，开发和本地联调成本可控；
- API 契约、日志和指标成为统一的运维入口。

### 代价

- 客户端需要逐步迁移为缓存与同步模型；
- 刷新令牌轮换、第三方通知和账本需要更严格的测试；
- PostgreSQL、Redis、后台 Worker 和密钥管理增加部署复杂度；
- 模块边界必须通过代码约束持续维护，否则单体仍可能退化。

## 明确不做

- 不在客户端保存 AI 提供商密钥；
- 不把 Redis 当作永久数据源；
- 不让支付收据本身直接等价于有效权益；
- 不允许客户端直接提交余额、订阅状态或“已解锁”最终值；
- 不把开发环境的单实例 Compose 视为生产高可用部署；
- 不在本地自托管 DeepSeek 模型；本地运行的是 LingoTrip 后端，模型通过受控服务端连接调用 DeepSeek API。

# iOS 后端接入约定

## 环境

- Debug 默认连接 `http://127.0.0.1:8080`，仅允许本机网络明文传输；
- Release 默认连接 `https://api.lingotrip.app`；
- 自动化测试和开发联调可用 `LINGOTRIP_BACKEND_URL` 覆盖地址；
- 生产构建不得通过环境变量或设置页接受用户自定义后端地址。

## 会话

- 客户端只把轮换用 refresh token、会话 ID 和用户 ID 存入 Keychain；
- access token 只保存在进程内存，并在过期前 30 秒刷新；
- 同一时刻的多个请求共用一次 refresh token 轮换，避免旧令牌重放误报；
- API 返回 401 时只自动刷新并重放一次原请求；
- refresh token 被拒绝后清除本机会话，要求用户重新登录；
- 无网络启动且 Keychain 中仍有未过期会话时，可进入只读缓存界面；首次需要服务端操作时仍会刷新并校验会话。

## 身份

- 邮箱注册必须完成服务端发送的验证邮件后才能登录；
- Apple 登录先从服务端获取一次性 nonce，再把 identity token、authorization code 和 challenge ID 一并交给服务端核验；
- Apple authorization code 和 identity token 不写磁盘、不写日志；
- 设备 ID 是 Keychain 中随机生成的安装标识，只用于会话管理，不作为用户身份或广告追踪标识；
- 退出登录以本地凭据清除为最终动作，即使服务器暂时不可达也不会保留可用凭据。

## 权威状态与同步

- 登录后先读取签名同步游标；有变更时重新取得一致快照，无游标或游标失效时执行受控全量同步；
- SwiftData 中的档案、金币和可用机票只是展示缓存，购票、旅行、首次解锁和剧情奖励都不接受客户端提交最终数值；
- 购票、旅行、剧情完成和新手机票领取使用持久化幂等 ID。网络响应丢失后重试仍复用原 ID，记录最多保留七天；
- 只有未到访城市由服务器要求并消耗机票，已解锁城市直接通行；
- 新手机票完成引导后只能领取一次；剧情金币按服务端剧情白名单进入不可变账本；
- App 回到前台时读取增量游标；离线时明确显示缓存模式，恢复网络后刷新界面；
- 账号切换会先清除整个本机账号域缓存，防止上一账号的对话、资产或资料短暂泄露给下一账号。

所有跨平台业务状态通过 `BackendClient` 接入同一套 `/v1` API。订阅权益和 AI 配额同样只读取服务器结果。

## StoreKit 订阅与权益

- 商品 ID 先从 `/v1/billing/products` 读取，再交给 StoreKit 2 获取当前商店地区的本地化名称、价格和周期；客户端不维护另一份可售商品白名单；
- 发起购买时必须把当前后端 `userId` 作为 `appAccountToken`，服务端据此阻止交易跨账号绑定；
- 客户端先完成 StoreKit 本地签名校验，再将原始 JWS 上传 `/v1/billing/apple/transactions`；等级、有效期、好友上限和 AI 配额只读取服务端统一权益快照；
- Apple 交易只有在服务端完成证书链验签、商品映射和数据库事务后才调用 `Transaction.finish()`；
- 未完成交易会在登录、恢复购买和 `Transaction.updates` 到达时补传。每个 Apple transaction ID 对应一个持久化幂等 UUID，响应丢失不会重复发放权益；
- `appAccountToken` 明确属于其他账号的交易不会上传，也不会结束；切换账号会停止旧账号的交易监听投影；
- App 回到前台时同时刷新业务状态与权益，普通业务快照合并时保留已经验证的计费投影，避免订阅等级被非计费接口覆盖；
- “管理订阅”使用系统 StoreKit 管理页；购买待确认、用户取消、恢复为空和验签失败分别展示，不把取消误报成错误。

本地数据库和普通功能联调不要求开启 Apple 计费。真实 Sandbox/Production 购买联调必须在后端配置 Apple 根证书、Bundle ID 与 App Apple ID，并通过 Sandbox Apple ID 或 TestFlight 产生 Apple 签名交易；开发调试路由只能用于验证权益消费界面，不能替代发布前的 Apple 验签测试。

## AI 中转

- iOS 只提交 `conversation`、`coach_review`、`speech_feedback`、`memory_summary`、`translation`、`character_generation`、`dictionary_explain` 等稳定任务名；
- 客户端不能提交供应商密钥、模型名、温度或任意服务地址；这些值由服务端版本化路由控制并接受审计；
- 普通完成使用 JSON API，角色对话使用经过认证的 SSE；取消界面任务会向上游传播取消信号；
- 结构化输出在客户端把 JSON Schema 作为约束提示附加，服务端仍决定该任务是否允许 `json_object`；
- App 升级后主动删除旧版本遗留在 Keychain 的第三方 AI 密钥和本地模型偏好；
- 服务端只记录任务、耗时、token 和状态等元数据，不把完整对话写入 AI 请求日志。

## 跨平台用户内容

- SwiftData 已迁移到 Schema V2，新增账号归属、服务端版本元数据和持久 outbox；迁移是轻量迁移，不会重建或丢弃原数据库；
- 主角色使用跨安装固定 UUID，避免每台设备把同一个内置角色上传成不同记录；
- 角色、会话、消息、收藏、角色记忆、答题记录和剧情断点都编码为严格的 v1 payload，通过 `/v1/content/commands` 同步；
- 首次接入时分页下载服务器记录，以服务器记录覆盖同 ID 本地缓存，再把只存在于旧版本本地数据库的记录作为版本 0 命令迁移上云；
- 每条本地写入保存账号 ID、资源 ID、父资源 ID、`expectedVersion` 和独立 `commandId`。只有服务端确认后才更新本地版本并移除 outbox；
- 流式回复的频繁文本落库会合并到尚未发送的同一命令；如果旧命令已经在传输，则保留旧命令并创建下一版本，避免响应回来后覆盖新文字；
- outbox 信号做 300ms 防抖，降低流式输出期间的请求数量；崩溃或断网不会清空 outbox，登录和回到前台都会继续发送；
- 版本冲突读取服务器当前记录：若本地没有更新的后继命令，就以当前服务器版本重新提交原用户意图；若已有更新版本，则丢弃过时意图并对最新完整快照重新编号；
- 服务端变更通过账号绑定的全局同步 cursor 下发，删除墓碑会删除本地投影；切换账号时会在显示新账号之前清除内容、元数据与 outbox。

SwiftData 中这些对象仍是离线可用的 UI 投影。客户端可以乐观显示普通内容编辑，但金币、机票、城市解锁、剧情奖励和订阅权益不进入这套通用内容协议，继续只接受专用服务端领域命令。

# LingoTrip 后端威胁模型

## 范围与资产

本模型覆盖公网 API、后台 Worker、PostgreSQL、Redis、iOS 及未来客户端、Apple 订阅接口、DeepSeek API、邮件服务、日志和备份。

重点保护：

- 账号控制权与设备会话；
- 邮箱、第三方身份、对话、语音等个人数据；
- 订阅权益、机票和虚拟货币；
- AI 提供商密钥、模型配置与费用额度；
- 审计记录、备份和运营后台权限；
- 服务可用性和跨用户数据隔离。

## 信任边界

客户端、互联网和所有第三方回调都不可信。客户端包内的常量、本地数据库、时间、设备状态和网络响应均可被篡改。Redis 可丢失；日志平台和运营人员按最小权限看待；只有经过领域校验和事务提交的 PostgreSQL 数据是业务事实。

| Access Token 被窃 | 越权访问 | 短时有效、受众/签发者校验、TLS、敏感操作再认证、会话撤销 | 过期/错误受众/撤销测试 |

| 日志泄露 | Secret/PII 扩散 | 字段白名单、递归脱敏、禁止记录正文、分级保留和访问控制 | 日志快照测试 |
| 错误详情泄露 | 暴露内部结构 | 生产统一错误、内部堆栈仅安全日志、稳定公开错误码 | 生产模式响应测试 |

| 删除流程不完整 | 合规风险 | 删除编排、第三方删除/匿名化、备份到期策略、删除审计 | 数据主体请求演练 |

## 认证安全要求

- 密码策略偏向长度，允许密码管理器生成的长密码，不静默截断；
- 登录、注册、重置接口避免通过响应差异枚举账号；
- 服务端不把原始刷新令牌、验证令牌或重置令牌写入数据库；
- JWT 密钥带 `kid`，支持双密钥平滑轮换；
- Apple 登录必须校验一次性 nonce，授权码不能在不同客户端重复使用；
- 高风险安全事件使对应会话立即失效，并写入审计日志。

## 数据与租户隔离要求

- HTTP 层从已验证令牌得到当前用户，忽略载荷中的权限声明；
- 仓储层以 `userId` 为必填范围，后台跨用户查询使用单独接口和权限；
- 当前数据导出使用已认证、`no-store` 的一致性响应且不创建临时副本；大文件方案才使用加密对象和短期下载凭据；
- 删除账号先冻结登录和新写入，再异步清理或匿名化，过程可恢复和可审计；
- 开发、预发布、生产数据严格隔离，生产数据不复制到个人开发环境。

## 密钥管理要求

- 仓库只提交变量名和空示例，不提交真实值；
- 本地使用未跟踪的 `.env` 或系统 Keychain，生产使用 Secret Manager；
- AI、邮件、Apple、JWT 和数据库凭据分别授权、分别轮换；
- Secret 不进入异常信息、遥测属性、命令行参数、构建产物或客户端包；
- 发现任何密钥进入聊天、工单或日志后，生产启用前必须轮换。

## 可用性与滥用

按层限制请求：

1. CDN/WAF 或负载均衡器限制明显攻击；
2. API 按 IP、账号、设备和路由限流；
3. AI 网关按 token、并发和费用预算限流；
4. PostgreSQL 连接池、查询超时和慢查询告警；
5. Worker 采用有上限重试、指数退避和死信状态。

健康检查本身轻量且限流，不能暴露版本、依赖地址或 Secret。

## 隐私默认值

- AI 提示词和回复默认不进入应用日志；
- 仅在用户明确开启诊断并经过采样、脱敏和短期保留后保存必要内容；
- 上游 AI 用户标识使用服务端生成的不可逆摘要，不发送邮箱或设备广告标识；
- 语音原文件除非功能明确要求，否则处理完成即删除；
- 分析事件使用最少字段，不与认证 Secret 或完整内容混合。

## 上线前安全门

- 通过认证重放、IDOR、幂等、订阅伪造、AI 配额和日志脱敏自动测试；
- 依赖无已知严重漏洞，镜像以非 root 运行；
- TLS、数据库加密、备份与恢复演练完成；
- 生产 Secret 已轮换且不与开发共享；
- 告警接收人、事故响应与密钥轮换流程已演练；
- 外部渗透测试或等价安全评估完成后再处理真实付费与敏感数据。

## 剩余风险

单一 AI 或商店提供商可能故障或改变接口；首期通过超时、熔断、降级和适配器降低影响，但真正多提供商容灾需在业务量与合规需求明确后实施。模块化单体共享数据库，应用级隔离错误仍可能影响多个模块，因此高风险路径必须保持事务测试与授权测试。

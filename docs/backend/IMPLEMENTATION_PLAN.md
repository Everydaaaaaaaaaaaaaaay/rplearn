# 生产后端实施计划

## 交付原则

- 每项工作独立提交，提交前通过该阶段的格式、类型、单元或集成测试；
- 数据库变更只追加迁移，不修改已经发布的迁移；
- 新模块先定义领域边界和失败语义，再开放 HTTP；
- 所有外部事件和客户端写入均按幂等设计；
- 客户端迁移期间保留可控降级，但订阅、资产和解锁一旦切换后不再回退到本地权威；
- Secret 只在运行时注入，示例文件保持为空；
- `main` 上的每个阶段都应能启动、回滚应用版本并保留数据兼容性。

## 分阶段提交

### 1. 架构与安全基线

提交：`docs(backend): 定义生产架构与交付计划`

范围：

- 记录技术栈、模块边界、权威状态与同步策略；
- 建立威胁模型、数据分级和上线安全门；
- 明确各阶段提交与验收条件。

验收：

- 文档不包含 Secret；
- iOS 本地状态与服务器状态的职责无歧义；
- 订阅、AI 和身份均有提供商中立边界。

### 2. 可启动后端工作区

提交：`feat(backend): 建立服务骨架与配置基线`

范围：

- Fastify、TypeScript、Zod、Vitest 工作区；
- 严格环境配置校验、统一错误响应、请求 ID 和日志脱敏；
- `/health/live`、构建、格式、类型检查和基础测试；
- `.env.example` 只列变量，不含值。

验收：

- 空依赖环境可通过一条命令安装并测试；
- 非法生产配置拒绝启动；
- 测试证明日志不会输出常见 Secret 字段。

### 3. PostgreSQL、Redis 与迁移

提交：`feat(backend): 建立持久化与本地依赖`

范围：

- Docker Compose 本地 PostgreSQL 与 Redis；
- Drizzle Schema、迁移工具、连接池和事务边界；
- API readiness 检查依赖与迁移；
- 统一 UUIDv7、UTC 时间和审计字段。

验收：

- 全新数据库可前向迁移；
- 重复执行迁移无额外变化；
- 集成测试使用隔离数据库；
- Redis 不承载唯一业务事实。

### 4. 账号、密码与设备会话

提交：`feat(auth): 实现账号与令牌轮换`

范围：

- 注册、登录、邮箱验证、忘记密码和重置；
- Argon2id、非对称 JWT、刷新令牌摘要和轮换；
- 设备会话列表、单设备与全设备撤销；
- 登录限流、账号枚举防护和安全审计。

验收：

- 注册到刷新流程端到端通过；
- 并发刷新只有一个成功；
- 已使用刷新令牌重放会撤销整个 family；
- Token、密码和验证码不出现在日志或数据库明文。

### 5. Apple 身份与账号绑定

提交：`feat(auth): 接入 Sign in with Apple`

范围：

- Apple discovery/JWKS 缓存和签名校验；
- issuer、audience、nonce、授权码时效校验；
- 身份绑定、冲突处理和恢复登录；
- 提供商接口为 Google/Web 身份保留扩展点。

验收：

- 有效沙盒身份能创建或登录账号；
- 错误 nonce、audience、签名或重放被拒绝；
- 不因 Apple 隐藏邮箱创建重复用户。

### 6. 用户资料与权威虚拟经济

提交：`feat(domain): 建立用户状态与资产账本`

范围：

- Profile、设置、等级、XP、当前位置；
- 机票与虚拟货币追加式账本、库存与城市解锁；
- “仅首次解锁消耗机票”的服务器事务命令；
- 管理型补偿操作带原因和审计。

验收：

- 并发首次旅行只扣一次；
- 已访问城市不扣机票；
- 余额可由账本重建且不能为负；
- 客户端提交最终余额会被拒绝。

### 7. 跨平台同步与幂等

提交：`feat(sync): 实现跨设备变更协议`

范围：

- 用户单调变更序列、墓碑和增量游标；
- Command Outbox 接收、幂等记录和请求摘要；
- 偏好、收藏、进度等资源的明确冲突策略；
- 游标过期后的快照恢复。

验收：

- 相同命令重复请求只产生一次副作用；
- 相同幂等键配不同载荷被拒绝；
- 两设备能从不同游标收敛到一致状态；
- 删除不会因旧客户端上传而复活。

### 8. 统一订阅与 Apple 验证

提交：`feat(billing): 建立订阅验证与统一权益`

范围：

- Product、Store Mapping、Transaction、Subscription、Entitlement；
- Apple 签名交易和 Server Notification V2 验证；
- 沙盒/生产隔离、事件幂等、乱序重算和主动补查；
- 面向客户端的平台无关权益 API。

验收：

- 伪造签名、错误 bundle/environment 被拒绝；
- 重复或乱序通知得到相同最终权益；
- 过期、宽限、退款、撤销能正确反映；
- Google Play 和 Web 支付可通过新适配器接入而不改 API。

### 9. DeepSeek AI 网关

提交：`feat(ai): 建立可配置 DeepSeek 网关`

范围：

- 提供商接口、任务路由、配置版本和审计；
- 所有开发路由默认 `deepseek-v4-flash`；
- Chat Completion、结构化输出、thinking 配置与 SSE；
- 超时、有限重试、断连取消、统一错误和用量记录；
- 服务端系统提示词与客户端消息分离。

验收：

- 无密钥时明确拒绝启动 AI 功能但健康的非 AI 服务可按环境策略运行；
- 使用运行时密钥可完成普通和流式请求；
- 客户端无法指定任意 URL、密钥或越权模型；
- 日志不含请求正文、回复正文或上游认证头。

### 10. 配额、风控与成本控制

提交：`feat(ai): 增加配额限流与费用保护`

范围：

- Redis 分布式请求/token/并发限制；
- 免费、订阅与内部账号的配额策略；
- 单请求输出预算、日预算、熔断与费用估算；
- 滥用事件和成本异常指标。

验收：

- 多 API 副本共享同一限额；
- Redis 短时不可用采用明确 fail-open/fail-closed 策略；
- 超限响应含稳定重试信息；
- 压测不能绕过并发和日预算。

### 11. 日志、审计、指标与追踪

提交：`feat(observability): 完善日志审计与遥测`

范围：

- Pino 结构化字段和递归脱敏；
- 独立业务审计事件；
- OpenTelemetry HTTP、数据库、Redis、上游调用追踪；
- Prometheus 指标、SLO 建议和告警规则。

验收：

- Request ID 与 Trace ID 可定位一次完整 AI/订阅调用；
- Secret 与 PII 脱敏快照测试通过；
- 指标标签无用户级高基数数据；
- 审计记录不能由普通业务接口修改。

### 12. 后台任务与数据生命周期

提交：`feat(worker): 实现可靠任务与数据治理`

范围：

- 数据库 Outbox/任务租约、重试、退避和死信；
- 验证邮件、密码重置邮件与订阅补查；
- 用户数据导出、账号删除/匿名化编排；
- 定期清理过期会话、Token、幂等记录和临时文件。

验收：

- Worker 崩溃后任务可恢复且副作用幂等；
- 导出只含当前用户数据并自动过期；
- 删除流程有状态、可重试、有审计；
- 邮件提供商故障不会阻塞 API 事务。

### 13. 容器、部署和恢复

提交：`ops(backend): 完成生产部署与恢复基线`

范围：

- 多阶段非 root 容器、API/Worker 启动命令；
- 本地 Compose 完整联调；
- CI 检查、迁移发布、滚动升级和回滚手册；
- Secret 轮换、PostgreSQL PITR、恢复演练和事故响应手册；
- SBOM、依赖与镜像漏洞检查入口。

验收：

- 新环境按文档可重复部署；
- readiness 在依赖故障时停止接流量；
- 最近备份可恢复到隔离环境并通过一致性检查；
- 旧应用版本在迁移后仍可安全运行或明确阻止回滚。

### 14. iOS 后端客户端与认证

提交：`feat(ios): 接入后端认证与会话`

范围：

- 平台无关的 `BackendClient`、错误模型和请求 ID；
- Keychain 保存刷新凭据，访问令牌内存缓存；
- 邮箱与 Apple 登录界面、会话恢复和安全退出；
- Debug 环境指向本地服务，Release 强制 HTTPS 生产地址。

验收：

- 冷启动可恢复或安全清除过期会话；
- 401 只触发一次受控刷新，并发请求不形成刷新风暴；
- 客户端不再保存 AI 提供商密钥；
- 网络错误具有可恢复的用户反馈。

### 15. iOS 权威同步迁移

提交：`feat(ios): 迁移用户状态到服务端同步`

范围：

- SwiftData 调整为缓存与 Outbox；
- 旅行、资产、资料、收藏和进度接入同步协议；
- 首次迁移本地历史的去重与冲突处理；
- 离线能力和重新联网收敛。

验收：

- 两台设备状态收敛；
- 离线重复操作不重复扣费；
- 服务端拒绝后客户端回滚乐观 UI；
- 本地迁移可重试且不会重复导入。

### 16. iOS AI 请求迁移

提交：`feat(ios): 通过服务端使用 AI`

范围：

- 将直连提供商改为 AI 网关任务路由；
- SSE 解析、取消、重试和配额提示；
- 删除用户输入第三方 AI Key 的产品路径；
- 保留 Mock Provider 用于离线测试和预览。

验收：

- 聊天、翻译、语法、记忆等现有能力映射到稳定任务名；
- 断网、超时、配额耗尽和模型故障均有明确 UI；
- 客户端包和日志不存在 DeepSeek Secret；
- 流式取消会终止服务端与上游请求。

### 17. 端到端与发布门

提交：`test(e2e): 建立商业发布验证门`

范围：

- Compose 端到端覆盖注册、登录、旅行、同步、订阅和 AI；
- 权限、IDOR、Token 重放、幂等和日志泄漏回归测试；
- 性能基线、容量假设和故障注入；
- 预发布清单与人工安全评估入口。

验收：

- 核心路径自动化通过；
- 容量和费用上限有可观测数据支撑；
- 关键依赖中断时行为符合降级策略；
- 上线安全门逐项有责任人与证据。

## 发布阶段

### 内部开发

本地 Compose、测试 Apple 沙盒、测试邮件服务和 DeepSeek 开发额度。使用模拟订阅事件覆盖难以触发的状态。

### TestFlight

预发布环境独立数据库与 Secret。先启用账号和 AI 网关，再以功能开关迁移同步和订阅权威状态。

### 商业发布

完成备份恢复、安全评估、告警演练和密钥轮换。AI 默认路由仍可使用 `deepseek-v4-flash`，但具体启用由成本、质量和合规评估确认。

## 完成定义

“生产级”不等于代码存在。每一能力只有同时满足以下条件才算完成：

- 有稳定契约与错误语义；
- 有自动化正常、边界和滥用测试；
- 有结构化日志、指标和必要审计；
- 有迁移、部署、回滚和恢复路径；
- Secret 和个人数据符合分级规则；
- iOS 及未来平台不需要复制领域规则；
- 在依赖失败、重复请求和并发执行时仍保持数据正确。

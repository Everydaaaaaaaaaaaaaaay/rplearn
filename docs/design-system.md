# LingoTrip 设计基础

## 当前方向

LingoTrip 的界面以“旅途场景中的轻游戏体验”为核心。城市与角色美术负责建立情绪和身份，
UI 负责提供清晰的信息层级与原生交互，不再用统一的卡片或夸张按钮覆盖每个页面。

四条原则：

1. **场景优先**：首页、剧情、活动和地图允许拥有自己的构图，美术素材不是卡片装饰，而是页面结构的一部分。
2. **原生行为**：导航、菜单、Tab、Sheet、滚动和辅助功能继续由系统组件承担，品牌层只重绘外观。
3. **克制反馈**：高频操作使用短促的透明度与轻微缩放；弹跳只保留给选角确认、奖励等低频时刻。
4. **按证据抽象**：至少在多个 Feature 中稳定重复的模式才进入 `DesignSystem`。业务专属构图留在 Feature 内。

## DesignSystem 的边界

保留：

- 动态语义颜色、间距、圆角、动画和城市场景色板。
- 触觉、材质降级、Tab 可见性等行为基础。
- 已跨页面验证的 HUD、模态框、头像、标签、消息气泡、富文本与旅行转场。
- `DSActionButtonStyle`、`DSSurface` 等不决定业务布局的视觉原语。

不收编：

- 首页探索入口、剧情章节卡、活动路线卡等带业务信息结构的组件。
- 仅为了减少几行 SwiftUI 而创建的万能卡片、万能 Hero 或复杂配置对象。
- 会改变系统导航、菜单、Tab、Sheet 原生行为的自绘替代品。

## 表面层级

`dsSurface` 只表达空间层级：

- `.grouped`：设置项、资料分组等页面内集合；有描边，无阴影。
- `.elevated`：位于页面背景上的独立内容；轻微阴影。
- `.floating`：叠在场景美术上的关键内容；更强但克制的空间层级。

场景大图、剧情卡和活动 Hero 应自行定义渐变与裁切，不套 `dsSurface`。

## 操作按钮

`DSActionButtonStyle` 使用单层表面和轻微按压反馈：

- `.primary`：全局主要操作。
- `.tinted(color)`：有明确业务语义的主要操作。
- `.secondary`：普通页面上的次要操作。
- `.glass`：放在场景图或深色渐变上的操作。
- `.destructive`：明确的危险操作。

旧 `DuoButtonStyle` 的 4pt 厚底与按下位移已删除。按钮不通过夸张的物理位移抢夺场景注意力。

## 新组件进入规则

新增组件前依次确认：

1. 是否已经在至少两个 Feature 中出现，并且信息结构确实相同？
2. 抽象后能否保留各页面的场景构图，而不是迫使页面看起来一样？
3. 是否保留 SwiftUI/UIKit 原生行为、Dynamic Type、Reduce Motion 与辅助功能？
4. 默认样式是否能直接使用，而不是依赖大量参数才能看起来正确？

任一答案为否，就先留在 Feature 内。

# UI 刷新边界与性能检查 · 2026-11-18

## 检查范围

静态检查覆盖 App 组合层和 13 个 UI 模块，沿状态读写、通知、计时器、手势、视图身份、图片准备与异步任务查找刷新传播。运行检查集中在聊天输入、消息菜单、翻译器、Tab 返回、联系人、赴约、个人资料、会员入口、城市活动与地图。摄影素材沿用已有验收记录。

| 范围 | 发现与处理 |
| --- | --- |
| App 组合层 | 活动协调器改为属性级 Observation。剧情进度留在活动子树，角标只在未读状态变化时更新。联系人变更由对应页面处理。 |
| 消息、联系人 Tab | 通过明确的重置参数关闭搜索和二级页面，保留列表实例、已加载内容与背景。联系人详情持有选中人物的快照。 |
| 消息列表 | 排序移到数据快照构建阶段。相同数据跳过赋值，通知合并到视图任务标识，隐藏页面在再次出现时刷新。 |
| 联系人 | 在线状态时钟位于联系人标签内，离屏与后台暂停。头像和会话通知按人物 ID 更新，异步结果按人物合并。 |

| 聊天与学习横滑 | 背景和分页直接读取同一手势状态，背景进度在独立子视图消费。键盘焦点与页面切换由聊天宿主协调。header 使用可收缩宽度及紧凑返回布局，修复学习页返回后工具按钮进入系统溢出菜单的问题。 |

| 世界地图 | 检查原生地图相机与标注边界。标注数据、选中状态相同时跳过重复图片设置、按钮配置和布局请求，操作回调持续更新。 |
| 学习与测评 | 检查题目、答题状态、音频模型和成就动画。升星、晋升动画已有独立 Timeline 与完成后暂停条件，测评页使用持续存在的页面内 header。 |

| 登录、引导、收藏、设置 | 检查局部状态、列表身份、查询与偏好入口。收藏词条在加载阶段准备，搜索消费内存快照。 |

## 测量方法

设备为 iPhone 18 Pro 模拟器，iOS 27.0，Debug 构建。聊天使用同一离线内存夹具和原生键盘，每轮输入再删除 `A quiet day by the river.`，共 3 次采样。CPU 与内存指标显式指定被测 App。

```swift
XCTCPUMetric(application: app)
XCTMemoryMetric(application: app)
```

| 指标 | 拆分聊天视图前 | 验证批次测量 |
| --- | --- | --- |
| App CPU 时间均值 | 0.9349 秒 | 0.6838 秒，降低约 26.9% |
| App 峰值物理内存均值 | 196,562 kB | 190,549 kB，降低约 3.1% |
| 自动化输入与删除周期 | 1.5294 秒 | 1.5408 秒 |

输入周期包含键盘事件注入与自动化等待。以上是指定负载的模拟器样本。真实设备的帧率、GPU 耗时和长时间内存趋势尚待实测。Xcode 27 的 SwiftUI Instruments 模板在当前模拟器报告 `Hitches is not supported on this platform`，本轮性能数值使用 XCTest 的 App 进程指标。

基线证据为 `20261118T065501Z-37138.xcresult`，最终测量批次为 `20261118T073523Z-46182.xcresult`，均位于 `build/DerivedData/VerificationResults/`。输入测量用例可单独复跑。[ChatViewPerformanceTests.swift](../../Tests/LingoTripUITests/ChatViewPerformanceTests.swift)

地图快速进入与拖动测试通过，同时报告了线程优先级反转诊断。该诊断在最终复测中仍出现，需要进一步获取设备线程等待栈。真机帧率、GPU 耗时和长期内存检查尚未完成。

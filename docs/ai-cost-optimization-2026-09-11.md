# AI 调用与输入缓存优化（2026-09-11）

本次实施联合点评精简、到期小测合并、后台失败降级、记忆合批/去重及输入缓存优化。
固定例句及翻译随词典提供仍按既定计划暂缓，没有进行全量预翻译。

## 调用变化

- NPC 主回复完成后，一次 `coach_review` 返回语法、关系、成长信号，并在到期时附带小测。
  不再从新版聊天流程发出单独 `quiz` 请求；保留旧客户端路由和历史账单兼容。
- 普通点评最多两条主要语言问题；无成长信号时返回 null，中性关系原因可为空。
  普通点评输出上限 1,000 → 700 tokens，带小测仍为 1,000。上限变化不等于实际费用同比下降。
- 点评失败只记录本地接触，不再回退发第二次 Coach 请求。客户端后台三类任务不自动重试；
  服务端原本已有单次尝试限制。用户可见的聊天仍保留原重试机制。
- 记忆原始聊天压缩仍为 24 条触发、每批 16 条，避免扩大阈值后丢出上下文窗口。
  分层整理最小溢出批量 3 → 6；同会话压缩互斥，失败后冷却 60 秒，游标不推进。
  输入记忆、输出事实进行保守去重；保留词序、否定、日期和标点，避免误合并不同意思。
- 小测在派发时重置周期；后台结果返回时不再抹掉等待期间新增的计数。

## 缓存措施

1. 聊天的时间、关系、成长与记忆上下文移至固定规则之后，不删上下文。
2. JSON Schema 固定排序并放在 system 最前；点评角色资料也使用固定 JSON 键序。
3. 记忆任务的当前时间移到可变输入段，保持规则前缀稳定。
4. OpenRouter 顶层 `session_id` 按匿名用户引用、任务和模型生成 SHA-256，稳定供应商路由，
   保留默认故障回退。不修改后台选定的模型，不向 GLM 添加不适用的 Anthropic 缓存标记。

粘性路由只减少切换，不保证每个供应商立即命中。管理员显式 `provider.order` 会优先于粘性选择。
官方依据：[OpenRouter Prompt Caching](https://openrouter.ai/docs/guides/best-practices/prompt-caching)。

## 真实小测试

从实际 `PromptBuilder.roleplayRequest` 导出固定的四轮合成书店聊天；时间每轮变化 75 秒。
这些是产品代码生成的测试输入，不是私人生产聊天。未填充无意义文本、未重复相同问题。
基线为本次修改前的 `1014345` 代码；优化组使用本次提示词布局及稳定 session_id。
两组均为 `z-ai/glm-5.3-flash`，温度 0.8，输出上限 120，沿用线上 provider_options。
顺序执行基线四次、优化四次，没有强制指定供应商。供应商直调，不扣任何用户积分。

按总缓存 tokens / 总输入 tokens 计算，包含未命中的前两轮：
**0 / 8,687 = 0% → 3,840 / 8,687 = 44.20%，提高 44.20 个百分点。**
这不是“请求有缓存的比例”；后者为 0/4 → 2/4。

上游返回的输入费用 $0.00084669 → $0.00056150，下降 33.68%；
含输出总费用 $0.00097769 → $0.00060490，下降 38.13%。
八次测试合计 $0.00158259，按后台汇率约 ¥0.0114。
供应商及其价格、生成输出和长度截断均有差异，不能将费用或延迟变化全部归因于缓存。
这是小样本路由+提示词联合实验，不是随机化试验，也不是长期生产缓存率承诺。
输出上限可能截断部分回复，因此本次结果只用于缓存计量，不作为对话质量评测。

# 成本与套餐实验设计 · 第二轮

本轮在 4172c26 合并版本上扩展评测，不修改生产权益或售价。先冻结场景再收集结果；分析保留中断与降级，不只挑成功会话。

## 采样结构

- 常见使用：6 种行为场景，各 3 个独立身份，共 18 个会话、234 个计划对话回合。包括初学游客、旅行碎片对话、职场学习、兴趣社交、角色探索、语音转写入口；覆盖小学起步、初中及大学英语三个等级。
- 压力使用：免费连续使用 32 回合、高级英语连续长聊 64 回合、三个 NPC 切换 36 回合，各一次。它们用于发现边界，不作为真实人群占比或稳定性估计。
- 常见会话名义账户预算合计 ¥10.50，显式实验预算 ¥12；压力会话名义预算合计 ¥2.50，显式预算 ¥3。真实消耗按账本汇总，名义预算不是供应商账户硬锁。
- 配置分别为 `Backend/config/cost-scenarios-study.json` 和 `Backend/config/cost-scenarios-stress.json`。模型和产品逻辑保持一致；记录源码版本、配置摘要、实际测试二进制、路由、费率及每次调用。

## 要回答的问题

1. 同一场景重复时，费用、完成度、缓存命中和辅助功能波动有多大？报告逐个样本及最小/中位/最大，不以 3 个样本声称人群 P95。
2. 免费用户是否在实际费用尚低时就被较大的预留额度挡住？区分余额耗尽、预留不足、功能回退和响应失败。
3. 长上下文与角色切换是否引发非线性成本增长？按真实轮次记录输入 token、后台记忆次数和累计费用，不把新身份重放称作跨日留存。
4. 输出是否可用？保存合成会话回复、角色生成响应及动作结果，抽查不空回复、场景相关性、纠错、记忆一致性及降级；格式成功不等于教学质量。
5. 正常时段、无缓存时的同用量费用有多敏感？周日只能实测空闲时段，高峰与取消缓存均为按官方费率重算的反事实场景。
6. 候选日额度/月池可覆盖哪些已测会话？包含实际预留峰值。被截断的会话只证明当前体验上限，不能外推完整需求为零。
7. 按 15% 渠道抽成，扣模型预算、免费补贴、退款税费缓冲与其他可变成本后，什么价格仍有合理贡献空间？所有未实测比例必须列为假设并给出失效阈值。

## 结论强度与停止条件

完成本轮可形成可执行的试运营价格、额度区间和成本护栏；无法由合成会话证明市场愿付价格。若出现系统性格式失败、账本未结算或额度阻断，先解释原因，再决定有针对性的追加实验，禁止为了得到好看结果无限重跑。

连续多日的真实使用、付费转化、长期留存、基础设施账单与获客费用另列证据缺口。完整语音音频/硬件功耗、公共 NPC 分配、共享后台任务也不可默认免费。本轮不把所有功能分成固定调用次数套餐，统一积分仍按缓存/普通输入/输出的真实金额扣减。

## 采样口径修订（运行中发现，保留原场景与证据）

2026-09-06 代码可达性检查确认：城市活动合并为离线 `ActivitiesView` / `ActivityActionView` 后，`EncounterService.generateEncounter` 与 `openingForExisting` 已无应用调用点。原“Plus 新角色探索”组三次测试继续作为能力基准，单列，不参与当前实际用户场景覆盖或售价权重。当前应用工作流实际为 5 类、15 个重复样本，另有 3 个角色生成能力样本和 3 个压力样本。此修订没有更改运行中的脚本或删掉不理想的结果。

最初尝试以两个隔离模拟器/后端并行运行，压力批次曾返回启动失败，后续数据库复查发现残留原生进程仍产生 7 次已结算调用（¥0.021465）及 2 轮完整记录，现以环境中断保留；恢复后全部串行运行，共享模型供应商账户。顺序执行仍可能影响跨身份缓存。每用户账本仍独立归因，供应商总余额差只用于总量核对，不冒充逐请求发票。

## 定向追加（根据已观察到的问题）

- 前两次免费旅行场景均在第 8 轮后因预留不足中断，分别剩余 42.9215、42.1893 积分。追加同脚本、同路由的 200 积分隔离账户对照，重复 3 次；`--free-credit-override 200` 只改变隔离数据库政策，原 100 积分样本原样保留。属于顺序对照，缓存和模型随机性仍可能影响结果，不宣称随机试验的因果精度。
- 首次并行运行造成磁盘/内存压力。三个已完成样本保留；社交 r1 在 6 轮后停止写入，账本继续保留，按环境中断排除完整体验统计。继续运行的选择过程在 `continuation-*.json` 中记录，只包含从未有原生记录及费用操作的身份。另补一个全新社交样本，不覆盖中断记录。
- 增量名义模型预算为免费对照 ¥0.60、社交替代 ¥1.20。全轮名义账户预算合计 ¥14.80，仍在最初为两批预留的 ¥15 范围内。预算按新身份相加，不把失败费用冲掉。
- 恢复后改为同一专用模拟器串行执行，新增启动前磁盘检查；共享供应商余额核对按每段起止记录，实际金额以隔离账户账本归因。

## 预留机制的反事实比较

当前产品总是用高峰价、输入字节上界、最大输出做预留。分析工具另算一条候选线：如果从预留到 5 分钟到期都处于空闲时段，则按空闲费率预留；只要窗口可能跨入高峰，仍保留高峰上界。使用同一批实际请求/结算时序，不更改线上代码，不将回放结果称为真实额度干预。该候选不会凭预期缓存命中降低预留，也不会删除失败费用。

压力批次在原报告生成后仍有残留进程写入，说明不能只读旧报告判断是否付费；恢复现在同时校验数据库及原生文件。该免费压力身份不会重跑；另建 32 轮免费压力替代样本，追加名义预算 ¥0.10，全轮合计 ¥14.90。64 轮及多角色身份仅在数据库与证据均确认未开始时继续。

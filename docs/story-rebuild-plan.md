# 剧情重构施工方案

状态：2026-09-06，制作流程、现实旅行/人物成长方向、主线 5 站与城市剧情 15 篇已确认。
用户先验收伦敦声音样板，随后在 2026-09-07 要求重新设计其余主线与城市篇。新故事集的剧本、声音与可玩接入见 `departures-collection.md`；其余站点专属美术尚未制作，旧正式剧情与进度保留。
实际脚本、美术和验收范围见 `story-london-production.md`；本文保留全量生产的后续门槛。

## 目标与边界

从头设计主线与城市剧情，交付可在手机上阅读、选择、查词和续播的精致竖屏视觉小说。
不以换立绘包装旧故事；保留已确认的 5 站规模，不沿用“五城回声”的旧叙事。
首页、“我的”、地图、城市活动和聊天不是本轮视觉重构对象。

- 全部新增视觉美术采用 AI 生产，不外包，不购买素材或擅自调用付费 API。
- 使用当前可用内置图像生成能力；额度不足时报告，不假设无限免费生成。
- 图像生成具体方式以执行时的 imagegen 技能与工具规范为准，不复制旧模型参数。
- 文字、按钮、查词、转场、微光等适合原生实现的效果由程序绘制，不烘焙进图片。
- 音频独立规划。图像工具不等于配音、音乐或环境声能力；未确认可用工具和授权前不承诺全配音。
- 不批量删除旧剧情，不直接覆盖旧进度；新内容通过验收后再切换。

## 已确认的制作原则

### 叙事与演出

主线提供持续动机、人物关系与选择后果；城市故事提供当地生活体验，和主线共享人物与地点。
英语用于解决剧情中的真实沟通问题，不让机械答题取代人物动机。
多数分支可汇合，但重要选择必须留下可读的反馈或后续状态，不能全是假选择。

交替使用环境镜头、人物对话、道具特写与关键事件插画。普通对话使用独立立绘；复杂递物、
接触、坐姿遮挡等优先设计专用构图，不强行拼接穿帮。每次新增机位、换装、天气或昼夜都计入资产。

默认不采用全程视频、全角色 Live2D 或持续循环晃动。渲染框架先以样章需要判断；
现有 SwiftUI 是接入起点，不因首页使用 Metal 就为剧情预设 Metal 重写。

### 一致性与生成

参考 [Assetelier 工作流](https://github.com/Haruhiyuki/assetelier/blob/main/assetelier/skills/assetelier/SKILL.md)
及其 [清单示例](https://github.com/Haruhiyuki/assetelier/blob/main/examples/asset-manifest.sample.json)，
借鉴风格基准、依赖顺序、固定母版、原始文件留存、合成验收，不安装或照搬其 CLI。

1. 先定义统一画风、镜头、比例、光线和材质规范，再确定角色与场景母版。
2. 角色变体始终引用同一已验收母版；同一地点的新构图引用固定场景设定。
3. 关键插画必须等待它依赖的角色和背景通过验收，明确每张参考图的用途。
4. 不用变体继续派生下一变体，不连续图生图修补整张画面。失败候选从固定母版重新生成。
5. 参考图驱动不能保证完全一致；必须检查脸部、服装、道具、空间关系及连续切换。
6. 透明立绘优先请求真实 alpha，不默认绿幕抠图；实际检查透明通道、发丝和深浅背景边缘。
7. 保留原始输出，确定性裁切、缩放和导出另存；不得拉伸变形或覆盖唯一母版。
8. 真实地点与物品先记录可靠图片来源，核对结构与在地细节。网上参考不自动具有交付素材授权。

## 当前代码基线与兼容约束

核对入口：

- `Packages/LingoKit/Sources/StoryEngine/StoryScript.swift`：line/choice/branch/reward/end，背景与单立绘字段。
- `Packages/LingoKit/Sources/StoryEngine/StoryPlayer.swift`：节点推进、布尔标记、进度通知。
- `Packages/LingoKit/Sources/StoryFeature/AVGStoryView.swift`：当前渐变/图案/说话人圆徽章占位演出。
- `Packages/LingoKit/Sources/DomainKit/Story/MainlineCatalog.swift`：5 个主线章节，主线城市默认开放。
- `Packages/LingoKit/Sources/DomainKit/Story/CityStoryCatalog.swift`：15 篇城市故事目录。
- `App/Resources/main_characters.json`：Oliver、Ruby、Marcus 的既有人设；也服务于剧情之外的产品体验。

旧 `journey-design.md` 中顺序解锁、地图底部引导的部分说明已落后于现有实现；
不得依据它恢复已移除的锁定或地图卡片。新剧情也不擅自改变当前城市经济与开放规则。
自由选章与连续叙事冲突时，先提出推荐顺序、前情说明或非线性结构方案，不能暗中添加锁定。

可复用现有节点与进度能力，但多人站位、明确清除立绘、表情、镜头、声音、字幕分级和状态恢复
需要新增演出契约与测试；现有 bg/sprite 字段不代表这些能力已实现。
新剧情的长期关系写入、奖励和角色解锁须核对服务端契约，不能只改本地 flags。

## 交付物与执行顺序

| 阶段 | 交付物 | 完成门槛 |
| --- | --- | --- |
| P0 施工基线 | 本文、创作方向草案、验收与风险约束 | 已确认原则和待决策内容分开 |
| P1 故事设计 | 世界与人物设定、全量章节大纲、分支后果表、演出脚本、初版资产计数 | 故事方向经用户确认；每个节点有用途，不依赖旧故事惯性 |
| P2 视觉规范 | 风格样本、角色/场景母版、图层与构图标准、代表片段详细分镜 | 视觉母版经用户确认；先验证难镜头再锁定全量制作规格 |
| P3 可玩样章 | 接入 App 的完整代表性片段、确定性状态恢复、QA 证据 | 用户确认；真机验证阅读、选择、查词、转场和连续切图 |
| P4 全量生产 | 定稿脚本、逐项美术需求、实际资产清单、原始与交付文件、逐章接入 | 每个资产与节点可追溯，所有分支均走通 |
| P5 切换交付 | 旧数据迁移/保留规则、奖励幂等、资源预算、回归与安装 | 无丢进度、误解锁或重复奖励；验收后切换 |

全量故事和资产需求先规划，但总资产数在脚本定稿后才能承诺；候选图、母版、表情、机位、
服装、时段、专用插画分别计数。样章是正式生产的第一段，不是不可交互的效果图。

仅保留三个创作确认点：故事方向、视觉母版、可玩样章。普通资产的逐项生成与质检由代理负责。
有重要角色重设、重大规则变化、额外支出或无法满足的生成限制时另行说明，不默认获得授权。

## 演出脚本契约（设计字段，尚非运行时格式）

每个节点记录：`storyID / version / nodeID / sceneID / shotID`，前置状态、人物与站位、
姿态/表情/视线、台词及语言版本、翻译、暂停/推进条件、转场、音效、引用资产、出口与状态变化。
分支记录即时反馈、后续兑现节点、是否汇合、完成与奖励条件。未设计的字段标注待定，不编造运行效果。

- 不同英语难度共享事件、情绪和选择后果，只改变表达；第一版支持哪些难度待设计确认。
- 打开查词/翻译时暂停自动推进；关闭、切后台、恢复前台不丢台词、不多跳节点。
- 快进与跳过明确处理尚未选择的分支，不以跳过绕过奖励/解锁判定。
- 断点恢复还原背景、人物、表情、镜头及分支标记，而不仅是下一条文字。
- 正式剧情离线使用预制脚本与资产，不在每次观看时生成图像或即兴改写关键事实。
- Supertonic 英文演出每个消息框不超过 65 个字符（含空格和标点，不是单词数），按语义
  人工拆分并逐框匹配中文。当前 FluidAudio SDK 在 70 字符处开始分块；保留余量，
  不调高引擎上限、不以拼接音频掩盖分段。升级 SDK 时重新验证真实阈值。
- 在脚本声明 `maxDialogueCharacters: 65` 并通过载入校验及语音边界回归。
  长句的分支/选择出口只放在最后一框，保持镜头、人物、故事含义与存档兼容。

## 资产需求与记录契约

每项记录下列内容，正式清单在 P1/P2 建立，不能以空占位项冒充已完成资产：

- 身份：稳定 ID、类型、版本、使用章节/镜头、状态（planned/generated/rejected/accepted/integrated/verified）。
- 依赖：固定母版 ID/版本、参考图角色（人物/空间/材质/结构），真实参考来源及使用边界。
- 美术：完整生成需求、不可变化特征、允许变化项、镜头与光照、材质、禁止项。
- 适配：画布尺寸/比例、色彩空间、alpha、人物包围盒、头部/眼睛/身体基准点、裁切与文字安全区。
- 演出：同屏比例、站位、朝向、切换时固定区域、适用背景、前景遮挡与绘制层级。
- 交付：原始路径、成品路径、生成方式、确定性处理记录、文件尺寸、字节数、验收问题与使用状态。
- 预算：母版/候选/成品数量分开，记录重试原因；连续 3 次同类失败先复查需求/机位，不无上限重试。

角色背景之间需做合成验收。尺寸正确不代表美术合格，alpha 存在不代表边缘干净，
身份一致不代表表情切换稳定。无明确证据的任务不得标记 verified。

## 验收标准

### 内容

全节点引用存在，入口/结尾可达，每个选择出口与后果覆盖；无意外死循环或软锁。
城市事件的地理、出行、职业和道具逻辑合理；不将生成的伪细节当作事实。
人物性格、知识范围和情绪衔接一致；重大选择后果能被用户察觉。

### 视觉与交互

在实际对话框、底部区域和设备裁切下验收，而非仅看原图。检查人物面部/手部/服装，
双人比例/视线，表情切换跳动，透明边缘色边，物体接触/遮挡，文字清晰度和明暗可读性。
覆盖小屏、大字体、Reduce Motion、安全区、快速连点、查词打断、自动播放与前后台切换。
文字不因美术而缩到不可读；长台词通过分页/布局处理，不一味缩字。

### 性能与迁移

先测当前基线，再记录样章首屏等待、切图帧耗时、峰值内存和章节资源大小，确定数值预算。
正式多站资源应按当前与下一场景预解码，缓存有界。伦敦独立预览暂限定最多 8 张图，
在后台一次准备，约 48 MiB 理论解码量；不得把它无界推广到全部章节。
模拟器不能替代真机性能验收。
发布需验证断网、资源缺失、旧存档、新章节版本、重复点击完成、重温与多设备同步。
旧内容 ID 不直接映射为新故事完成；奖励是否补发/复用须先定义，再和服务端一起实现。

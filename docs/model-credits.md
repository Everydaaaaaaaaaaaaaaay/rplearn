# 统一模型积分：试行规则与成本边界

本方案替代「聊天与角色生成次数／语音秒数／专项解析次数」作为模型调用的计费限制。角色生成是 AI 根据外出活动等上下文产生新角色卡；遇到已存在的角色无需因此调用生成模型。它与聊天的发生频率、输入长度和输出长度都不同，不应按同一次数定价。

## 用户规则

一个账户只有一份用户模型积分余额。聊天、角色生成、主动语法讲解、单词讲解和翻译按实际用量扣费；自动纠错、记忆整理、主动问候、小测和语音反馈由独立产品预算承担。本地词典、端侧语音识别、端侧朗读和复用缓存结果不产生模型费用。语音租约只控制会话生命周期和并发，不再按语音秒数收取另一份额度。

1 元模型费用对应 1,000 显示积分。这是成本计量单位，不是人民币储值、现金、金币或机票，也不是单独出售的余额。模型调用次数和新角色数量都不是套餐承诺。

| 游客 | 一次性 200 积分 | ¥0.20，永不恢复 | 3 |
| 免费 | 每日 100 积分 | ¥0.10/日 | 5 |
| Plus（内部 pro） | 每日 400 积分 | ¥0.40/日 | 10 |

登录用户统一按 UTC 自然日恢复（北京时间 08:00），未用完不累积。升级提高当天预算，保留当天实际已消耗；降级不删除成果、不返还消费，也不重新发放积分。订阅有效性继续以服务端验证的权益为准。

剧情旅伴不占普通好友位。游客不能飞往其他城市、剧情只开放各条线的首站；登录解除身份限制，仍须遵守游戏进度。现有分档记忆容量保持不变。新角色登记有独立的反滥用上限：游客累计 30，登录用户每日 90（包含已有登记逻辑中的待分配项）；这个上限不是付费权益或保证产量，和积分、场景复用及角色一致性共同约束生成。

## 定价现状与实测优先

第二轮已形成[实测结果](user-cost-study-results-2026-09-06.md)与[试运营建议](cost-pricing-proposal-2026-09-06.md)：候选为 Plus ¥39 / 12,000 月度积分、Pro ¥59 / 20,000 月度积分，免费采用每日补充与余额封顶。它们是供评估的后续政策，**尚未替换本文上方的现行每日预算**，也不表示订阅已上架。完整样本、回退和中断费用分别保留，不能将模拟工作流当成真实月度用户分布。

渠道抽成按用户确认的 **15%** 计算。此前 ¥68/¥198 月费与 30% 抽成的推算已撤回，不作为上架依据；¥39/月和月度积分池也只是待验证的候选方案，尚未改变线上预算或商品售价。

先运行 [`user-cost-evaluation.md`](user-cost-evaluation.md) 中的端到端成本工作流，观察常见用户会话、辅助调用占比、额度中断和长上下文，再比较价格与周期预算。不能把短会话重复乘 30 当成真实月度用户成本，也不能把额度截断的会话当成低成本的成功样本。

贡献余额 = 实际结算收入 − 模型费用 − 免费/游客补贴 − 其他可变运营成本。固定成本、人工、获客、税费和退款还需另计；没有付费意愿与留存证据时，模型成本只用于判断价格是否可持续，不能证明用户愿意购买。

## 精确结算与异常处理

- PostgreSQL 是权威余额；金额使用整数纳元（1 元 = 10^9 纳元），BigInt 运算，无逐次向上取整。显示积分可保留 6 位小数。
- 每次调用固定一个 operation ID 和请求摘要，数据库账户锁串行化准入与结算；相同 ID 不能重复派发，参数变化冲突。完成结果短期可重放，费用历史和请求 ID 不因结果缓存过期删除。
- 开始时只检查用户实际余额是否大于零，不要求余额覆盖估算费用。剩 1 积分也允许已接受的操作在原有输出和超时限制内完成；完成后按真实用量扣除。实际已消耗可超过当日额度，可用余额显示为零，下一次请求才被拒绝；已接受的操作和幂等结果重放不受影响。
- 用户请求不预留、不冻结。数据库旧 `reserved_units` 列及 `reserved`/`dispatched` 状态仅保留估算和生命周期审计。独立产品辅助预算仍用保守估算控制后台成本；分钟限流、输出上限和超时保持有效。
- 派发时保存供应商、模型、价格版本、来源、生效时间及派发时刻的单价。当前 DeepSeek 峰谷规则和价格来自 `Backend/config/ai-prices.json`。未来 GLM、混元等需实现各自用量和费率适配，不得套用 DeepSeek 折扣。
- 使用供应商返回的普通输入、缓存命中输入和输出分别计价，校验缓存命中+未命中=总输入、输入+输出=总 token。缺失、不一致或模型身份不符，标记待核对，不将未知费用写成零或假装精确。
- 单次请求关闭供应商隐式重试，防止只计最后一次费用。新的显式请求独立记账。已派发但缺少有效用量的请求保留未知费用记录，不占用户额度；尚未派发的失败不扣费。缺失 `[DONE]` 的流视为中断，已取得有效终态用量仍可结算真实费用。
- 客户端断开后，已派发的流继续在供应商超时上限内收取末尾用量。下游背压等待在关闭或错误时结束，上游仍能继续结算。派发前取消不调用模型。
- 待核对记录可跨日保留供运维核账，但不冻结当前或下一周期余额。迟到的有效用量仍归属原请求周期。完整响应但缺失用量时仍可交付与重放内容，未知费用不会被伪装成已确认的零费用。
- 实际费用超过估算或剩余额度时如实记录，不截断、不转为冻结，也不跨日借记新的每日额度。估算不是供应商硬支出上限。
- 价格表和 token 乘积的精确性不同于账单对账：供应商的账单舍入、税费、汇率、计价时刻差异须用供应商账单核对。当前其他币种/新增缓存写入收费均不可未经适配启用。
- 自动辅助任务使用独立产品预算。共享词典例句首次翻译目前仍按真实用量计入发起用户，后续命中共享缓存不扣费；本次修改不改变各任务的计费归属。

## 运维与发布

迁移 0013 新增独立 `credit_operations` 和试行预算 `service_metadata.model-credits-v1`，不将旧计次账本的数字改解释为金额；原始历史保留。新预算从启用时开始，旧操作 ID 继续防重放。该次迁移会给已有游客一份新的积分试行预算，这是一次性切换，不是周期恢复。

配置金额均为纳元字符串；版本必填，免费→Plus→Pro 每日预算必须单调不减。调整前应核查真实商品售价及已购权益说明，不通过修改积分汇率暗中缩减权益。

- `pnpm credits:report`：只读分档/任务/供应商/模型/价格版本账本汇总，以及前 1,000 条待核对请求；不输出聊天内容。历史估算报表 `pnpm usage:report` 继续保留，不能替代这个结算账本。
- `pnpm credits:reconcile USER_UUID OPERATION_UUID CNY "供应商账单依据"`：有数据库权限的运维根据凭证结算指定待核对项。不存在面向客户端的退款或修改费用入口；不可凭超时自动填零。
- 运营清理只删除一天后的重放内容，不删除消费和待核对记录。
- 客户端显示可用、实际已消耗和最近 20 笔；未结算显示“用量核对中 · 不占额度”。为兼容旧客户端，`reserved`、`pending`、`heldCredits` 字段保留但返回零，后台原始审计估算不删除。
- 原有冻结记录不需要清零、退款或破坏性迁移：新余额算法仅扣实际已结算金额，部署后历史待核对项自动停止占用余额。
- `pnpm credits:report` 增加原始 token 用量、返回模型和请求状态；可结合 `usage_missing`、`usage_invalid`、`model_mismatch` 与网络中断原因定位结算问题。不要仅凭截图推定具体供应商故障。
- 生产迁移前备份，准备与新增迁移计数兼容的回退版本；回退旧程序会恢复旧计次数限制，因此只作紧急回退，不作为平行运行策略。多实例必须一起更新，避免计次/积分两套限制同时服务请求。

本任务的验证与生产启用状态以最终交付记录为准，本文不是发布成功凭证。

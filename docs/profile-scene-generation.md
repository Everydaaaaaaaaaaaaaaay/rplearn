# “我的”页场景图片生成约束

## 唯一母版

所有后续图片优化必须始终使用以下当前运行时场景作为唯一编辑目标：

`App/Assets.xcassets/profile_modern_travel_desk_interactive_scene.imageset/profile_modern_travel_desk_interactive_scene.png`

禁止以上一轮生成图作为下一轮输入。每次修改都应回到母版，并把已经确认的设计要求重新写入完整提示词，避免桌面纹理、地图、物品轮廓和光照发生代际漂移。

## 必须保持的母版品质

- 825 × 1906 的构图、裁切与视角。
- 桌面木纹、现代世界地图、路线、自然光照和真实材质的清晰度。
- 物体比例、阴影、透视与遮挡必须符合真实桌面摄影；允许按当前方案从母版重新替换物件，但不得沿用生成图中的材质与几何。
- 左上角相片圆圈内的头像必须平面嵌合，不能作为全息入口处理。

## 现代旅行物件约束

- 整个场景只允许一本书册类物品，当前为左下角的随身英语短语本；不得重复出现笔记本、护照本、日记本或书形钱包。
- 功能载体使用可一眼辨认的真实现代旅行用品：旅行证件夹、微单相机、拉链旅行钱包、平板、短语本、智能手表与显示电子登机牌的手机。
- 耳机盒、旅行转换插头等附属物必须独立、真实地放置，不能再使用同时收纳耳机、插头、取卡针和笔的虚构托盘。
- 禁止出现用途不明的盒子、设备、提示灯、幻想道具、装饰币或无法解释的零件。
- 物品之间只允许符合真实使用习惯的轻微压放，保持清晰分区与足够留白。

## 当前 UI 方向

- 背景图片只包含桌面、地图和真实旅行物件，禁止烘焙任何功能图标、标题或用户数据。
- 记忆、收藏、设置、登录等固定入口也与动态入口共用 SwiftUI 组件，避免图片文字与代码文字风格不一致。
- 图标和文字统一使用参考稿的暖黄色全息投影：实体核心约为 RGB(254, 249, 236)，衰减光晕约为 RGB(249, 232, 182)；金币也保持同色，不使用高饱和琥珀色抢夺视觉注意力。
- 不使用石墨、金属或其他现实固体材质。
- 全息层与承载物保持相同透视，但悬浮约 20–25 mm。
- 通过清晰全息层与承载物表面失焦光迹的视差表现高度。
- 不生成按钮底板、发光矩形、边框、光柱或强烈霓虹效果。
- 每组图标与文字占承载物可用面积的约 60%–80%，保证手机尺寸下醒目可辨。
- 画布顶部至少 170 px 保持安静，状态栏与灵动岛范围内不得放置文字、图标或关键物件。
- 运行时不得给所有入口套同一种倾角。旅行证件夹、相机、钱包、平板、短语本、手表和手机分别保存独立的 Z 轴方向、X/Y 轴透视、纵向缩短率、光迹落点与发光厚度。当前母版实测长轴方向依次约为 −13°、+7°、+13°、+4°、−12°、+16°、+3°，图标与文字的基线必须与对应长边平行。
- 全息入口默认完全静止，不运行循环悬浮、呼吸或亮度动画。Z 轴方向服从物件长边，X/Y 轴透视仍保持克制，防止文字被过度压扁而难以阅读。
- 文字不得越过承载物的有效区域。英语旅程图标和三行信息完整排在平板屏幕内部，以较大的垂直间距利用屏幕高度；护照资料文本完整位于上半页内，头像则嵌入下半页的证件圆框。

## 运行时渲染架构

- 普通字号下的场景页禁止使用 `ScrollView`、下拉刷新或回弹拖拽；画面固定在视口中并裁切，避免用户拖动后露出顶部空白或破坏入口与实物的对应关系。仅辅助功能超大字号继续使用独立的语义化滚动列表。
- 场景背景必须同时延伸到顶部与底部安全区，并隐藏当前页 Tab Bar 的整条默认背景；系统浮动 Tab Bar 本身继续保留原生材质，禁止在其后方出现白色色带。
- 全部视觉以 402 pt × 928.7418 pt（825 × 1906 母版比例）的唯一参考画布排版。背景、图标、动态文字、微光、投影足迹和点击热区必须先共同放入该画布，再对整张画布做一次统一变换；禁止按设备分别重算或取整各入口坐标。
- 常规 iPhone 按屏幕宽度等比缩放参考画布。对于 iPhone SE 等短屏，再以最低入口的完整可见底边 682 pt 作为高度上限同比缩小整张画布并水平居中；两侧极窄余量只能使用无交互的同源背景柔化填充，不能移动任何单独入口。
- 不允许用非等比拉伸适配设备。不同机型可以裁掉最低入口以下的纯背景，但功能入口之间、入口与承载物之间的相对位置、角度和尺寸比例必须完全一致。
- `TextRenderer` 分别绘制字形主体、暗色轮廓、内层微光与外层低强度光晕，避免把动态文本预先栅格化进图片。
- 微光采用参考稿的三段亮度结构：暖黄色实体核心保持约 0.99 不透明度；内光晕半径约 2.3 pt、图层透明度约 0.60；外光晕半径约 6.2 pt、图层透明度约 0.32，并使用更深的金黄色衰减。另加不足 1 pt 的暖白边缘高光，恢复发光体的实体感。不得继续放大半径或用高透明度宽模糊把笔画连成白块。
- 参考稿中具有明确造型的金币堆、上升路线手册、星标书签与云形账户图标使用可缩放矢量路径实时绘制；记忆、设置和个人资料可使用几何一致的 SF Symbols。所有图标共用同一线宽规则和克制微光，禁止用含义相近但轮廓明显不同的填充图标代替。
- SwiftUI 的双轴 `rotation3DEffect`、局部 Z 轴旋转与轻微纵向透视缩短共同建立空间关系；Z 轴使用母版中物件长边的实测方向，X/Y 轴只保留轻微空间深度。三层亚像素错位副本表现发光体厚度，第二份低透明度、失焦且带视差的内容表现物体表面的投影足迹。
- 不再使用证件夹和钱包下方的椭圆光环或扇形光线；入口的悬浮关系仅由字形微光、轻微厚度和柔和投影足迹表达。
- 每项入口的中心点必须与母版上对应物件的几何中心对齐。手表和手机尤其不能沿用近乎水平的默认角度；调整场景图片或裁切后必须重新逐项校准。
- 只有用户按下入口时使用短促、可中断的弹簧反馈；所有入口都保留原生 Button/NavigationLink 语义和 VoiceOver 标签。
- 当前固定俯视场景不使用 RealityKit：母版只有二维像素，没有相机标定、深度图和对应物件网格。直接增加 `RealityView` 仍需人工重建七个载体的几何、虚拟相机与光照，且更容易和照片错位。只有未来提供准确的 USDZ/网格与相机参数，或将整张桌面重建为实时 3D 场景时，才升级到 RealityKit。
- 当前不使用 Core Image 透视滤镜：它更适合处理已经栅格化的图片，会削弱实时文本、动态类型和辅助功能能力。
- Metal Shader 预留为后续可选增强，仅在需要扫描线、折射或逐像素噪声时引入；基础光晕无需为此增加 GPU 管线复杂度。

# 城市活动：社交场景首个试点

## 定位与范围（2026-09-06）

城市活动的主闭环是「行动 → 合理相遇 → 交流和选择 → 自愿建立联系 →
继续聊天 / 再次相遇」。英语是交流工具，不再用匿名练习取代人物关系。
公园、池畔退出正式场景入口；旧行动足迹、好友、聊天和素材母版不删除。

首个试点选「街角咖啡馆」：普通城市日常的交集，不限定来客职业、年龄或爱好。
三个物件入口分别是共用座位、交换周边建议、聊一本随手翻到的书。编排相遇条件
和选项意图，先确定稳定人物，再生成符合其身份的短回复；不预设用户性别/音色。

## 施工顺序

1. 素材先行。新前景仅一次生成，无生成式 UI，无多轮图生图修补；保留母版和
   提示词。选择固定机位、多个不同路人完整经过且有空场的授权实拍。动态只在
   窗户内，窗框构成真实遮挡；窗口与物件共用照片坐标，不播放整屏漂移背景。
2. 只开放一个正式场景，保留可横向扩展的顶部场景条。复用已有 ivory hologram、
   物件四角投影、0.12 秒按压和 App 交叉隐现 / 左缘返回。三个入口可完成不同交流。
3. 复用稳定角色库。25% 的机会尝试本机合理重逢，否则或无合适人选时查询公共候选；
   重逢要求同城、未移除、非主线角色，距离上次交流至少 24 小时，明确语言设定不能
   与英语交流冲突。不按年龄、职业、爱好或头像供给筛人。新动作共享一个稳定上下文，
   不用随机 run ID / 自由文本作为 activity ID。失败不伪装成功、不反复制造新人。
   本机同城未移除人物可用于合理重逢；只在用户真正开启相遇后执行库查询。
4. 每次相遇提供明确缘由、已有身份、两次有不同后果的选择、短句英语解释；可
   礼貌告别。角色回复根据身份和已选分支生成，不把用户选择自动当作获得友情。
5. 实际呈现的对话写入同一角色的会话；幂等追加，取消未出现的回复不落库。
   添加好友遵循原有名额与注册/同步规则；继续聊天由 App 注入 ChatFeature。
   加载失败可重试/退出，保留既有身份，不覆盖私有关系与记忆。
6. 验证角色复用、移除排除、分支与幂等、取消、聊天衔接；仅使用 c955 绑定模拟器
   进行真实界面验收，记录截图、素材边界和未完成项后作独立提交。

## 素材与动态验收门槛

- 初筛拒绝：4147 市集（机位过高、密集人群无空场）、3428 街道（延时动作）、
  4451 夜街（地域招牌明显，不符合本次通用咖啡馆光照）。
- 候选 4169：固定机位、不同步行者、多段前景空场。须逐帧选取完整经过事件，
  背景固定只保留前景通行带的运动；不能切断身体或用溶解隐藏仍在场的人。
- 合格事件用无连续重复的洗牌顺序与空场间隔，正常播放速度，不镜像/倒放/复制
  人物；人物身份不与互动 NPC 绑定。有限片段不是无限真实人流，明确素材上限。
- 暂停/后台/减少动态/低电量/高温降级；只有一个可见播放器，无每帧 SwiftUI 更新。

## 查漏补缺一轮

- 人设与缘由分离：拿着菜单不等于美食家，翻书不等于书迷，来咖啡馆不等于喝咖啡。
  不为匹配头像改写年龄/背景；缺头像沿用待补图机制。
- 用户控制自身行动，不控制 NPC 同意；离开不惩罚，不保证每次都会成为好友。
- 稳定公共身份 ≠ 已与当前用户见过；熟人问候以实际本机会话为证据，不杜撰回忆。
- 不自动购买、不消耗金币、不假称真实定位、实时街景或真实商家。
- 历史数据和失败数据保留；明确本机记录和服务端登记各自状态，重试不产生重复聊天。
- 大字体可读替代入口；面板可滚动，文本不能被底栏遮挡，退出不会误触底层入口。

## 明确后续范围（不冒充本轮已完成）

自由文本「随心探索」、公共库跨活动语义检索/验证、服务端 reserve/reveal/commit
接口迁移、多场景扩展，在首个社交场景验收后接入。本轮不预加载公共候选，避免把
未进入的场景记成相遇；服务器旧接口在选择时记录曝光的限制仍需后续协议升级。
普通开发不包含生产部署、真实 AI 压测或手机安装。

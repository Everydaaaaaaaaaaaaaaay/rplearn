## 已确定的方向

沿用 [机制分析与实施设计](../../appointment-story-design-2026-10-30.md) 的自由输入、事实与人物边界、弹性长度、关系与记忆证据规则。按用户本轮补充，背景采用赴约城市的几张实拍慢速轮播，不随剧情切换、不绑定精确 POI，不因缺少某家店的照片限制故事。

选图还需尽量避开应用已有题材。用户明确举例伦敦双层巴士；本次也排除了来源记录中已用的塔桥、大本钟和圣保罗大教堂，另选运河、公园和街区。候选不等于最终美术验收通过。

## 页面与导航

聊天中的约定卡和活动页“赴约”打开同一份约定详情。多条约定时，入口先展示“最近可赴约/待继续”的一项及数量，再进入按时间排列的列表；详情页不承载复杂的日历。故事进行中返回活动只暂停，卡片主按钮变成“继续这次相处”。

| 位置 | 主要内容 | 主操作 | 次要操作 |
| --- | --- | --- | --- |
| 活动入口 | 角色小头像、下一次时间、进行中/可赴约状态 | 打开约定 | 多项约定列表 |
| 聊天约定卡 | 已说定的时间地点、城市与状态 | 查看约定/继续赴约 | 回看约定上下文 |
| 约定详情 | 城市照片、角色、当地时间与设备时间、地点、主题、预计相处时长 | 去赴约/继续 | 商量改期、取消 |
| 故事 | 城市氛围、当前场景标题、旁白/对白、选择和自由输入 | 回应当前情境 | 查词、翻译、回看、暂停、结束 |
| 总结 | 角色回望、好感变化、选择与后果、精选记忆 | 返回同一角色聊天 | 全文回看、管理记忆 |

正式导航由 App 装配，原型中“返回聊天”只解释目的地，绝不发送消息。独立总结可以从已完成约定再次打开；回看不改选、不重新生成、不再次结算。

## 约定页的具体设计

上部保留一段城市风景，标题采用现有剧情接近的衬线气质，下部暖纸色内容层呈现约定。视觉强调顺序是人物、时间、地点、操作；不显示关系分数，不在赴约前提示“选对可以加分”。

伦敦示例为 **2026 年 10 月 31 日周六 15:00（Europe/London，GMT）**，对应北京时间 **23:00**。两地时间都带明确归属，不能仅标“今天三点”。这里“今天”为演示场景设定，正式 UI 必须由可信时间计算，历史约定不继续显示“今天”。

地点名称保留双方商定的叫法，例如“南岸 · 滑铁卢桥附近”；背景可以是同城其他风景，照片信息入口清楚标注城市氛围。原型中的纸面承载时间信息，不将其压在复杂照片上。

| 约定状态 | 画面变化 | 操作与规则 |
| --- | --- | --- |
| 暂无约定 | 温和空状态“下一次见，慢慢约。” | 去与角色聊天，不自动创建约定 |
| 已约好，未到时段 | “已约好”标签；显示何时可进入 | 主按钮不可进入，改期和取消仍可用 |
| 可赴约 | “可赴约”标签、深蓝主按钮 | 首次进入创建或恢复唯一正式会话 |
| 已开始/暂停 | 标签“进行中”，按钮“继续这次相处” | 入场窗口过期也可以恢复 |
| 时段已过 | “这次没赶上也没关系” | 回聊天商量下次，不扣分、不责备 |
| 已取消 | 时间地点作为历史保留 | 不允许打开新的正式会话 |

“商量改期”回聊天，新提议经双方同意后替换旧时间。取消会关闭本次入口，故使用一次明确的 Sheet 确认；普通返回、翻译切换和暂停不弹确认。

## 故事页的具体设计

界面上半部留给城市氛围和轻量标题，下半部为暖纸阅读层。角色头像只作为说话人标识，不先制作整套立绘或表情。英语正文为主，中文对照可切换；旁白与对白有清晰层级。

默认每个决策点提供 2—4 个有不同意图的选项，选项下可显示中文。“自己说一句，或做点别的”保持独立且容易触达，不把自定义输入隐藏在更多菜单。自由输入 Sheet 允许 500 字以内的原文，空白不允许提交；上限是建议值，不代表模型能力限制。

选择提交后锁定这一轮，生成中明确说“你的选择已经保留”。失败提供原地重试，不能重抽角色或把错误变成剧情。正式产品的时间由服务端状态驱动；原型可从外部下拉框直接切换这些状态，未用人工等待模拟网络。

| 状态 | 呈现 |
| --- | --- |
| 阅读 | 按段推进，仍可查词/翻译/回看；不能越过选择替用户行动 |
| 等待选择 | 可执行选项 + 自定义入口；不出现推测剩余总块数 |
| 自定义输入 | 明确问“你想怎样继续”，支持文字和动作；关闭时正式版本应保留草稿 |
| 生成中 | 只冻结当前提交；允许暂停离开；故事记录仍可查阅 |
| 失败 | “这一段暂时没接上”；原地重试、稍后再来 |
| 自然结束/主动告别 | 当块给出合理告别，再进入独立总结 |

顶部的历史入口只回看实际路径。更多菜单提供暂停背景、回看、暂时离开和“今天就到这里”。正式版本中，选择“结束”会生成自然收尾，且只结算已发生部分；原型用预写收尾演示。

## 总结页的具体设计

顶部城市照片形成一次经历的封面，显示故事标题、角色、城市和日期；下方连续滚动的纸面承载回顾，底部固定返回聊天操作。总结不以大幅奖励动画或红绿分数作为主视觉。

阅读顺序为：

1. 角色一句简短回望，允许温暖、平静、尴尬等不同感受，但不能替用户宣布其情绪。
2. 本次关系变化，显示实际 delta、before/after 和简短原因。算法未完成时明确“待结算”，不以 0 冒充。
3. 按顺序回看选择：当时处境、用户原文、实际后果；自定义原文标“自己说的”。
4. 已保存的精选记忆、管理入口。
5. 返回聊天与完整经历回看。

正向、不变、负向、待结算均有原型状态。负向状态使用另外一条明确施压的演示路径与相应角色反应，不能把“提前离开/想安静坐着”配成扣分原因。数值仅为排版和状态展示，不是评分规则提案。

正式版应显示本次事件自己的 before/after，与同期聊天造成的变化区分。记忆管理支持编辑和不再使用；原型仅演示“不再用于聊天”，不会调用真实 MemoryStore。

## 城市照片准备

这次新增的三张来源均指向 Wikimedia Commons 文件页，已保存下载元数据和选用文件哈希。预览使用原始下载字节，采用 CSS 显示裁切，没有生成或重绘照片。头像复用已有 Oliver 头像，仅用作角色识别。

| 画面 | 作者与许可 | 选择原因 | 本轮观察 |
| --- | --- | --- | --- |
| 小威尼斯运河 | Matthias v.d. Elbe · CC BY-SA 4.0 | 运河船与树影，提供水边生活感 | 全图能识别运河；窄屏上横向船体会被裁切，需原生构图复查 |
| 樱草山 | LatteKnowledge · CC BY-SA 4.0 | 公园与远处天际线，与交通/地标特写不同 | 横向地平线不宜强行填整张长屏，预览把主要照片放在上部可见区域 |
| 诺丁山街区 | Bex Walton · CC BY 2.0 | 彩色住宅与街区纹理 | 原图包含街灯及路牌，预览不依靠读牌，需避免把私人住宅表现为可进入场所 |

署名随照片信息入口提供，链接到源页及相应许可；后续导出裁切照片时记录改动并履行相应署名与许可要求。这一包仅为本地设计候选，不宣称已经完成全部发布合规或原生验收。

首轮建议每城 3—5 张，单张停留 18 秒，0.7 秒淡化，无推拉/横移。输入、弹层、查词、后台时暂停，降低动态效果默认静态，可手动暂停。照片不参与推断故事天气，也不要求剧情转场时切图。归一化亮度与颜色应在正式选图后少量处理，优先换图而非重滤镜。

本次使用现有来源记录和实际画面建立了伦敦题材排除项，但没有声称穷尽所有历史资源或为其他十四城完成选图。正式素材检查仍需覆盖已用照片、插画、视频海报与剧情缩略图，比较题材而不只比较文件哈希。

## 尺寸、交互和无障碍

| 项 | 初始建议 |
| --- | --- |
| 原生布局基准 | 393 × 852 pt；复核 375 × 667 pt 及大字 |
| 文字 | 系统字体；标题可使用原生 serif；英语正文约 18—20 pt，中文约 14—16 pt；随 Dynamic Type 调整 |
| 主按钮 | 最小高 49 pt，横向填充，圆角约 14 pt |
| 触控 | 正式版所有可点击目标至少 44 × 44 pt；视觉小图标扩展命中区 |
| 阅读层 | 暖纸色高不透明度；降低透明度时使用实色，不用多层薄玻璃叠加 |
| 按压与 Sheet | 即时高亮/轻微按压，避免阻塞输入；Sheet 使用原生交互 |
| 长内容 | 阅读区/总结区滚动；短屏优先保留可达操作，不缩小字体硬塞 |
| 焦点 | Sheet 打开进入内容、关闭回触发控件；输入失败定位到错误；VoiceOver顺序与视觉一致 |
| 背景 | 无障碍默认不读轮播图片；照片来源是主动查看的独立信息 |

浏览器的“大字/短屏预览”用于暴露排版问题，不能替代 Dynamic Type、系统键盘、原生手势和 VoiceOver。原型的一些次要说明文字比正式建议小，交付 SwiftUI 时应按原生字号和真实设备重新排版，不能逐像素复制浏览器缩小后的截图。

## 施工顺序与边界

先锁定约定/会话/选择/结算的身份与状态契约，再做只读 fixture 页面与本地恢复，随后接在线生成和校验，最后接关系与记忆。保留原设计中对关系单一写入者、持久去重和严格同步 schema 的要求。

照片按 `cityID` 取目录，叙事只保存约定与合理的场景状态，禁止把同城照片清单当作剧情可行动空间。这样新增城市照片不会要求重新生成故事，角色换话题也不会迫使美术补图。

本轮只准备界面与参考材料。未新增后端模块、迁移、Swift target、真实关系事件或 App 资源，未安装模拟器构建、未部署。正式施工的运行代码、真实 AI评测与原生视觉验收另行记录。

## 发现与优化顺序

1. **角色生成存在付费后不可用的响应。** 探索场景第一次生成时，模型连续两次返回合法 JSON，但把 `anchor_lines` 写成对象；[EncounterService.swift](../Packages/LingoKit/Sources/DomainKit/World/EncounterService.swift) 要求字符串数组，解析失败后使用本地角色模板。两次无效响应花费 ¥0.003204 和 ¥0.003561，合计 ¥0.006765。第三次调用才返回可用数组。应优先改进结构化输出与可观测的解析恢复，并复测角色质量和失败成本。本任务保留原始行为，未用修复后的结果覆盖基线。
2. **辅助调用不能忽略。** 每轮对话都伴随审阅；应对照测量审阅频率、合并或模型路由优化后的成本与纠错/关系质量，避免仅凭省钱删除学习功能。
3. **当前短会话没有耗尽额度。** 这不能证明额度足够，也不支持立即普遍加量。需要补充长上下文、多个 NPC、密集学习、连续多日和不同价格时段的样本，再确定周期预算及是否采用月度积分池。

探索会话中还存在脚本对新 NPC 使用 Oliver 称呼的问题，后续准备脚本已改为中性问候。原样本继续保留并标为降级，排除月度成本外推。

## 定价含义

自动化测试能回答一次体验花了多少钱，不能证明用户愿意付多少钱。此前 ¥68/¥198 售价推算已经撤回；¥39/月、12,000 月度积分只保留为候选，未上线。当前游客/免费/Plus/Pro 的积分预算与生产价格均未修改。

例如 Pro 社交样本本次花费 ¥0.1654737。若保持完全相同的 token 用量，取消缓存优惠，按本次时段费率计算为 ¥0.2077905；再按当前正常时段费率翻倍，得到 ¥0.415581/会话。若进一步假设每月 25 天每天一次，约为 ¥10.39/月。**这是一组反事实计算，不是实测月成本或用户成本上限**，未包含跨日上下文增长及新增活动。

按用户确认的 15% 渠道抽成，¥39 的渠道后收入为 ¥33.15。以上述假设成本 ¥10.39，再假设其他可变成本 ¥5、每位付费用户补贴 3 位每月模型成本 ¥3 的免费用户，剩余约 ¥8.76，仍需承担固定成本、人工、获客、税费和退款；若免费用户比例升到 10，余额便为负。报告提供 ¥29/39/59/79 与不同免费用户比例的敏感性计算，输入假设必须用实测替换，不能将余额称为净利润。

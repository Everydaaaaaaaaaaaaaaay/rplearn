## 2. 实际发现与修订

| 定位 | 原问题或旧句 | 本版处理与理由 |
| --- | --- | --- |
| RB20 → RB21 | 选项只说“明天下午？”，结尾直接写用户同意了四点 | 选项先明确“Tomorrow at four, here?”，Ruby 再确认。没有偷偷替用户接受一个新时间 |
| TO20 → TO22 | 用户先说想分担，之后才出现九加元，旁白直接写支付 | 决定前先说明三十六总价、可由主人全付或自愿每人九元；选择文本明确“my nine dollars”。不在金额未知时写成同意 |
| SG20 → SG21 | 提议合照后，角色才加“只留给我们”，旁白替用户接受条件 | 提议本身改为“One photo together, just for us?”，角色同意同一范围；账本不包含公开许可 |
| RB22 | 直接离开线说“The next line is better. No toast in it.”，吐司笑话只在 RB10 出现 | 改为“Next time, a leaf. I'll practise.”，回到共同开场已经出现的拉花。未选路径不进入共同记忆 |

| TO00 | Sam 对 Maya 工作群里会议室回复开玩笑，却没看过那个群 | 补上 Maya 展示发错群的手机画面。人物不能凭空知道别人的消息 |
| TO21 | 先说下单完成、等餐，后面才写付款 | 将 Maya 付款放在收到用户确认之后、等待之前；不是在结尾补一笔发生顺序不明的费用 |
| MW00 | 两张都是同一人的远景/近景，首稿却说“两个人都同意”；又容易与旧篇 Elena 的撤展混为一谈 | 明确本候选是 Jo 的花店新作，并由 Jo 同意本场展示；不以“新篇”覆盖旧拒绝或旧分支成果 |
| MW11 | 标题场景只有最后一块空位，结尾却临时替另一张找到入口展位 | 保留 Marcus 选择近景，把用户偏爱远景的反馈兑现为说明卡的地点信息；没有制造第二块已经完成的展位 |

| AK21 的账本 | Hana 提出喝茶，账本一度写成可以回忆“一起喝茶” | 收回为“她提出喝茶”。邀请不等于接受，更不等于完成 |
| SG22 | 同一路径里先拿起行李，最后又“拿起行李”一次 | 第一处改成吃完饭且还有时间，最后才拿包离开；空间动作连续 |
| RB10 / OM11 | 申请已改成电脑填写，却仍把咖啡从纸表上挪开；Oliver 整理二十分钟后仍拿起先前烧的水直接泡茶 | 分别改为挪离电脑、重新烧热水。生活道具不是仅为了象征主题出现 |
| RT11 / RT22 | “keeping my place in two ways”需要解谜；“Missed the boat. Literally”容易被当成错过返程交通 | 改成需要公交座位、只顾看袜子而没看见船；结尾仍实际赶上返程车 |
| MW10 / 多篇末尾 | “No right answer”反复提醒考试；部分末尾像事实账本，而不是故事 | 删去考试提示，用看照片、收卡片、关手机、扶门等动作结束；未完成状态保留在账本里 |

奥克兰正式旧稿的“尚未交代借出却要求归还”另作根本修订：本稿开局 Peter 先明确归还上周借的工具，工具箱从此始终在 Hana 身边；后续 Peter 带走的是自己的抽屉和记录。本版改题《工具箱回到桌上》，使标题与新时间顺序一致。新稿成立不表示正式旧资源已修复。

## 4. 人物、成人生活和语言检查

| 维度 | 本版证据 | 判断 |
| --- | --- | --- |
| 角色区别 | Oliver 围绕书的取舍、演出和慢写作开冷幽默；Ruby 会把路线画满、把咖啡拉坏再删计划；Marcus 对照片坚持意见，并以准时到场改变行为 | 有可辨认差别；以后仍需读者检验，不能只凭三种职业判定成功 |
| 用户不是固定的开导者 | 可以只坐着、吃完离开、不同意照片、暂不约电话、不帮搬书 | 八篇都有自己的参与选择；没有靠一段劝说替角色解决人生 |
| 角色会回应用户 | Ruby 接受预算与返程限制；Maya 自己负责厨房和点单；Marcus 不把下一堆工作塞给用户 | 行动层面体现双向关系；没有全都顺从用户，MW11 保留真实分歧 |
| 简单英语能改变事 | “Tomorrow at four, here?”可约时间；“Not yet”可暂不约；“I'll take the chair”可只旁观 | 意图短且有可读后果；全文仍需要基础阅读或中文辅助，不能声称零基础无障碍 |
| 纠错时机 | 本批正文没有主动语法纠正或课程化表扬；事件只处理当前安排、兴趣和分歧 | 避免每段都变成教学；尚未覆盖用户主动求语言帮助的完整互动，不能据此验收未来聊天纠错实现 |
| 关系变化 | 旧午餐、主动重新约、下一次先到分别有证据 | 写出一次小的可靠性变化；不宣称角色从此永不迟到，也不默认和解 |
| 轻松内容 | 拉花、歌、蛋糕、袜子、茶与收书有实际动作 | 不要求每篇讲道理；幽默是否好笑仍待用户阅读反馈 |
| 现实与虚构 | 食品费用、线路、周二和明天均在本稿世界内；用户故事偏好单独记录 | 不把故事选择写成现实个人事实、实际付款或新地址 |

## 5. 离线检查及其边界

使用临时只读 Python 检查文稿，未将检查程序加入仓库。解析每篇入口、七个场景标题、A/B 前往和结束标记，从入口遍历：所有出口存在，无环，全部节点可达，每篇四条路径，合计三十二条。每个结尾在事实账本的结尾表中恰好有一行。

逐行检查 383 框正文与 48 条选项英文均不为空、均有中文，最长 59 字符；Marcus 后续的 31 行也在 65 字符内。非空和计数只证明格式，双语含义由上述复读补充检查。检查了本准备包本地链接与来源引用，并在提交前检查暂存差异和空白问题。

本轮没有构建或安装 App，没有修改 App/Resources、Swift、TypeScript、生成工具、生产提示词或配音；没有部署、线上探测或调用付费生成。工作树中其他任务的未提交代码不属于本提交。

## 6. 仍需保留的界限

- 这是八篇场景故事和一条后续小稿。其余十五篇正式故事仍按原评估保留或等待轻修，尚未交付新稿；亦未逐人重写两百位公共 NPC。三篇新增候选不自动成为正式增加的篇目。
- 主稿采用一个直接英语版本，没有交付每个能力档位的完整改写。初学者选择借助中文仍然成立；真实读者的负担、阅读时长和情绪反应没有实测。
- 八篇用同一种四路径骨架方便完整审查，正式编排时应按事件节奏决定停顿和选择数，不应给每次见面强行塞两次二选一。
- Ruby 申请仍未在本篇提交；后续若要展开结果，须另外写有证据的提交和回复事件。其他角色目前主要交付承接事实，只有 Marcus 三次接触写成完整小稿。
- 出游线路是虚构编辑模型。以后采用具体真实地点和实拍时，要把交通、空间和时段重新核对，不能将本稿价格或钟点当作可靠旅行信息。
- 尚未核对真实配音节奏、镜头匹配、小屏阅读、查词或跨设备恢复。这些需要未来明确进入实装和资产制作阶段；本次不据此启动代码、图像或语音生产。

下一轮内容工作可以继续扩写其他篇章与人物生活线。实际代码和正式资源的修改仍按用户本轮“先不实装”的要求保持延期，不因文稿完成自动开始。

# 学习升星与晋升动效提案

2026-10-27。用户希望升星时有精致的星体由远及近飞入空槽，升档拥有正式的专门页面。
本文件为设计建议，尚未接入运行中的奖励或晋升动画；本次实际代码改动只收紧学习卡片布局。

## 升星：星体出现 → 飞行 → 落槽，约 1.4 秒

- 0–200ms：背景轻微压暗，新星目标槽保留轮廓并出现一圈低亮度光晕。
- 200–650ms：有厚度和倒角高光的暖金星体从画面中央偏上方的远景接近镜头，由小变大，作轻微侧转；尾迹短而收敛。
- 650–1150ms：星体沿柔和弧线飞向本次新点亮的实际星槽，缩到槽位大小，最终姿态与九星行一致。
- 1150–1400ms：槽位变实心金色，一次小幅弹性回落、一圈向外消散的细光环和少量碎光；落点配一次轻触感。
- 同次得到多星时依序进入各自槽位，合并庆祝时长；不在画面上同时堆满飞行星体。
- 已点亮的星保持稳定，新增星的终态与静态星行共用同一种造型和颜色。

推荐用 SwiftUI 的关键帧和自绘分面星体表现厚度、明暗面与掠过的高光。
飞行按实际槽位锚点计算终点，适配小屏、大字及不同星数；避免使用截图里的固定坐标。

触发安排在挑战结果关闭、角色学习页恢复可见且服务端新星数已读取后。当前实现的积分会在答题回执中确认，
`CharacterLearningModel.challengeClosed()` 随后重新读取全局旅程；后续接入时应传递本次获得积分的回执，
以同一档位的旧/新星数确定新槽位。首次载入、普通刷新、打开历史、手动切换水平均不触发。
成功的奖励回执用来去重展示；动画结束或用户跳过都直接落到真实终态，不改变积分和星数。

## 晋升：独立全屏仪式，揭晓约 2.5–3 秒

1. 服务端确认进阶资格后显示“开启晋升”入口。除了九星，还保留课程目标、迁移练习和下一档内容等既有资格检查。
2. 独立页面采用深靛蓝背景、细腻暖金光和居中的档位徽章；原档位与九星先出现，角色用一句英文祝贺，主体留给成就本身。
3. 继续现有进阶剧情和最终确认流程。服务端保存晋升成功后，九星向中心汇聚，徽章展开，新档位名称清晰揭晓。
4. 成功页面停留供用户观看，只有一个主操作“开始新的旅程”；回到学习页后显示新档位及其真实星数，原档历史保留。

视觉重点放在星体、徽章与新档位文字三个对象，采用小范围光晕、金属倒角和柔和光扫；背景稳定。
晋升揭晓阶段允许跳过动效直接查看结果，确认按钮与重试操作不等待装饰动画。

项目已有 `LearningPromotionServing`、`LearningPromotionView` 以及带修订号/档案版本的晋升保存合同，
可在此基础上重做展示层。现有角色页摘要尚未提供晋升入口，后续需要同时装配入口和档案刷新回调。
资格、故事推进、确认及完成状态仍以现有服务端流程为准。

## 无障碍和验收

- 减少动态：星槽直接点亮，保留短暂辉光和文字确认；晋升页采用淡入，无镜头推进或远距离飞行。
- 后台、离开页面、旋转或字号变化时重新核对布局，取消悬空的飞行层并落到真实终态；恢复时不重复庆祝。
- 覆盖第一颗/第九颗/同次多星、零奖励、幂等回执重试、跨档切换、退出动画、失败重试以及大字/小屏。
- 连续观看原速动效并保留录像；截图只核对构图和终态，不作为飞行节奏或平滑度的通过证据。

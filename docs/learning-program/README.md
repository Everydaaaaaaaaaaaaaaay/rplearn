# 英语学习系统扩展工程

状态：**对话学习系统 v1 已于 2026-09-25 从正常产品流程撤下，等待新设计；当前状态见[进度账本](status.md)。**

人教版初高中英语的官方单元与资源入口已整理为[教材参考库](textbooks/pep/README.md)；目前尚未核对整册教材正文，不能将该目录当作正式挑战题库的内容证据。

2026-09-22范围说明：当前执行以[对话学习合同](learning-system-v1.md)为准，围绕原聊天、文字沟通与听力深化，不做口语/发音评判。下文为2026-09-16的历史研究规划，独立背词、跟读评分等条目是候选记录，不是当前实施指令或上线承诺；不得据此推翻用户后续确定的范围。

## 1. 我们要解决什么

用户希望把咕游记从“能在聊天时查词的英语通讯软件”，升级为“以虚拟旅伴和情境交流为核心，有系统学习能力的英语学习产品”。背词、复习统计、影视例句是研究起点，不是范围上限，也不是可以直接照抄的功能清单。

核心结果是：用户能记住、听懂、说出并迁移运用所学内容，清楚自己的进展，而且愿意持续学习。打开次数、聊天条数、收藏量、在线时长和连胜天数不能单独证明学习有效。

坚持：
- NPC 仍然是有性格的虚拟朋友，不因学习方向变成全天候授课老师。强训练放在用户主动进入的学习场景，聊天中的辅助轻量、可拒绝、可关闭。
- 给时间少的用户短路径，也给有明确目标的用户连续练习；不能只依赖自觉查生词。
- 借鉴机制与交互原则，不复制品牌、美术、文案或无授权内容。好看的界面不等于有效教学。
- 不预设“所有发现都要做”。每个新增系统都要胜过保持现状，也要证明为什么应当放进我们的软件。
- 不把整项工程绑定为一次大改版；逐批研究、验证、开发、发布，保留撤回能力。

## 3. 研究范围：先广泛，后深入，再定期补充

**研究重心（2026-09-16 用户补充）：以手机 App 为主。** 多邻国按用户追加要求列为重点深研对象，研究课程、反馈、复习与激励，并区分热度与学习成效。网站主要用于官方帮助、研究文献、App Store 界面与官方演示取证；不投入大量时间深测纯网站。不能将网页实测或商店宣传截图标记为手机 App 实测。优先补齐移动端内部任务流程，登录受限则记录缺口并推进其他可访问对象。

启动后第一轮暂定：快速扫描 20–30 个产品，覆盖下列至少 8 类；从中选 8–12 个做完整任务实测。数量是覆盖目标，不是“看够数量就完成”。遇到高重复产品停止扩张；连续两批未出现新的机制类别且主要学习问题已覆盖，可结束首轮扫描。以后每个功能批次补充 2–3 个针对性比较即可，避免无限调研。

下表全是**候选研究对象，不是已验证的功能结论**；产品可用性、地区、版本和付费条件需实测后记录。用户亲见墨墨的三档选择及统计属于研究线索；影视例句产品尚待确认。

| 类别 | 候选对象 | 要回答的问题 |
| --- | --- | --- |
| 背词与间隔复习 | 墨墨、扇贝单词、不背单词、百词斩、Anki、SuperMemo | 如何决定复习时间？自评与实际回忆如何结合？怎样处理积压和难词？ |

| 阅读与材料学习 | LingQ、Readlang、Beelinguapp | 词汇熟悉度、长文阅读、点击解释和复习怎样贯通？ |

“广泛参考”必须包含不适合我们的反例。每类至少记录一个优点及一个摩擦/失败点，不只写赞美。

## 4. 必须联网取证、看到实际画面，但证据有等级

联网调研是硬性要求：必须实际搜索并打开权威来源，包括产品官网、官方帮助中心、当前官方演示和算法原始文档；学习效果依据可核验的原始研究或可靠综述。搜索摘要、模型记忆和经验只能生成检索线索，不能代替阅读来源或完成产品分析。记录检索词、访问日期、原始 URL、对应论断与证据位置。官方营销对效果的宣称也需要独立检验。

产品内部具体功能和流程必须通过实际操作或可核验的内部画面确认，不能只看落地页。网络或账号受阻时标记未验证，继续其他可访问对象；不能退回凭自身理解补全。

每个进入深度比较的机制，走完一次真实任务：入口 → 开始 → 做对/做错/模糊 → 反馈 → 退出恢复 → 统计或复习结果。记录实际操作、等待、误触、默认项与隐藏成本。

证据等级：
- **A：直接操作当前产品**，记录平台/设备/地区/版本/日期，保存关键截图；动效或时间顺序用短录屏和时间点。
- **B：当前官方演示、帮助文档、商店截图**。可以确认画面或官方说明，不能据此推断自己没操作到的反馈、算法和跨日行为。
- **C：独立评测、用户描述或旧资料**。用于发现线索，不作为核心功能验收依据。
- **D：我们的推测或设计设想**。单列，不写成竞品事实。

每个拟实施功能至少有一条与机制直接相关的 A 证据；访问受阻时可暂以 B 形成假设，但必须标注并做自己的可交互验证。不能为了“已调研”伪造截图或把自制效果图当成竞品画面。

登录、付费、设备不可用不会让整项工程停摆：记录阻塞，研究可访问部分和同类替代品；确实需要用户提供访问时，提出具体缺口。不得绕过付费墙、访问限制或自动购买订阅。

后台调度、长期效果与数据同步不能靠一张图判断：结合可重复的行为测试、官方技术说明和学习研究，保留不确定性。

## 5. 用统一问题评价，而不是收集功能名称

每张研究卡需说明：
1. 谁在什么场景遇到什么学习困难？
2. 用户实际要做哪些动作，正确/错误/退出后发生什么？
3. 可能的学习机制是什么：提取练习、间隔复习、可理解输入、纠错、反馈、交错练习或迁移？哪些有外部证据支持？
4. 它减少了什么负担，又增加了什么负担？
5. 能否用我们已有语境和组件实现？放在哪里？怎样退出？
6. 需要什么数据、素材权限和持续费用？离线能否用？
7. 怎样证明用户学得更好；什么结果会让我们放弃它？

学习科学结论必须给出可检查的原始研究或可靠综述，标明适用人群、任务及局限。竞品采用某算法、展示某增长数字，都不直接证明适合咕游记。

## 6. 暂定产品闭环与信息架构

**遇见内容 → 理解 → 留下需要学的内容 → 主动回忆 → 间隔复习 → 新情境使用 → 看见可信的进展。**

候选入口（不是布局限制）：允许新建页面、底部 Tab、独立学习系统和新的交互设计。按学习任务选择承载方式，不要求全部塞进当前聊天、收藏或设置页；保留聊天、旅伴及其他已有优秀能力，不为新增训练而推翻它们。
- 聊天/剧情：轻量“加入学习”、可追溯的词句来源；讨论结束后可选小结，不在每句话后弹题。
- 收藏：仍是用户保存内容的地方；允许选择哪些加入学习，不把旧收藏全量强塞到待复习队列。
- “我的”中的学习入口：今日短练习、到期复习、目标与统计；可以直接设计独立学习页或学习 Tab，由任务规模、可发现性和实测决定。
- NPC：仅在合适语境自然复现目标表达；优先与当前话题相关，用户无兴趣时立即回到正常聊天。学习目的的倾向保持轻微，不能把之前的“约 10%–15%”当成每个会话必须达成的硬频率。
- 咕咕嘎嘎：承接显式讲解和练习指导，短、可略过；避免把所有 NPC 都改成批改老师。

示例假设：用户与 Ruby 聊天遇到 `unwind` → 可选加入学习，保留原句与来源 → 当日短练先回忆意思再揭晓 → 选择“认识/模糊/忘记”并完成一道可选听辨或补全 → 后续按计划复习 → 在不同场景自由使用。这个例子只用于说明整合路径，未做效果承诺。

## 7. 候选功能组合与优先级

### A. 第一批优先验证：语境词句复习 + 可信统计

最小纵向闭环要包含内容进入、一次练习、下一次安排、记录、统计、离线恢复；不要先花数周做一套空数据大屏。

- 单词、短语、表达和语法点可逐步支持；第一批只选一种或两种内容，避免调度模型过早泛化。
- 三档自评“认识/模糊/忘记”是交互候选。先给回忆机会，再展示答案和评分，减少看过答案后产生“我会了”的错觉。
- “认识”不自动等于长期掌握；结合客观回答、延迟回忆、提示使用情况。识别、听辨、拼写和自由运用分别记录，不能一个按钮让全部技能满分。
- 比较成熟间隔复习方案（如 FSRS）、简单可解释基线及实现许可；三档按钮与算法评级的映射必须显式设计、测试。无足够历史数据时用保守默认，不宣称已经个性化拟合。
- 对“忘记”安排短期重学，对“模糊”缩短间隔，对“认识”逐步拉长；具体参数在算法评估后确定。提供撤销误评、跳过、暂停、移出、每日上限、积压分摊与高频难词处理。
- 第一版统计回答“今天学了什么、完成多少、还需复习什么、最近是否进步”，不做知识量虚假排名。

### B. 第二批候选：把输入变成输出

- 用已学词句做听辨、短听写、遮挡字幕、跟读、复述及渐退提示。
- 易错表达的短练习与延迟复测，区分口误、可接受变体和真正错误。
- 在新的句子或话题里使用，测试迁移，不仅重复原题。
- 用户可选“只听”“听后看文本”“正常聊天”，与已实现的自动朗读形成连续体验。
- 发音反馈优先可理解度和可行动建议，必须单独验证噪声、不同口音和语音识别误差；不能把 ASR 转写差直接等同于发音差。

### C. 第三批候选：真实素材学习

- 先验证片段复读、双语字幕、单词跳转、上下文、导入学习队列是否真的有用，再决定建设素材库。
- 优先明确许可的教育内容、公版素材、自制素材或来源允许的官方嵌入；流媒体截图、字幕、音轨和短片段均需检查权利范围，不能因为“很短”就默认可用。
- 对每条素材保存出处、时间码、字幕来源、权利凭据和可用地区。平台允许播放，不等于允许下载、截取、商业再分发或离线缓存。
- 没有合法可实施来源时，该内容源延期，训练机制可用合法替代内容继续验证。自制内容须明确标注，不能包装成真实影视片段。
- 允许探索个人导入，但先界定仅本地处理、同步范围、分享限制及隐私；不把它当版权问题的自动解法。

### D. 持续发现项

阅读分级、词族/搭配、词义消歧、写作改写、考试目标、旅行任务、诊断式练习、无障碍、学习负担管理等均在研究范围内。上述顺序是可推翻的初始排序，不限制新发现进入优先级。

## 8. 功能筛选与取舍

先过门槛：学习问题清楚、机制可解释、证据来源明确、与聊天定位兼容、有合法内容方案、成本与数据边界可控、能单独验证和撤回。缺一项则补证据或延期。

通过后用 0–5 分评估，按 100 分折算：学习收益 30%、与真实情境的契合 20%、研究证据可信度 15%、用户操作负担 15%（负担越低分越高）、覆盖人数/频率 10%、实现与运行可持续性 10%。研发工作量另列，不能让低成本小功能天然压过高收益必要基础设施。

分数只是排序助手：同时写最强反对理由、证据不足处和会改变决策的事实。状态只可为“补证据 / 原型验证 / 小范围实施 / 延期 / 放弃”，不因研究卡写得完整就自动开发。

## 9. 数据、统计与算法底座

建议概念模型，待工程审计后映射实际表和 DTO，不在当前阶段创建迁移：
- 学习材料：稳定 ID、词形/义项/短语、语言、来源类型、原句与翻译、来源引用、内容版本；同词不同义不可简单混成一张卡。
- 学习事件：账号、事件 ID、材料 ID、任务类型、自评、客观结果、提示程度、发生时间/时区、设备及内容/调度版本。写入幂等，跨设备重传不重复计数。
- 复习状态：由事件计算的到期、间隔及算法状态，可重算；客户端离线可给临时安排，服务端合并后给一致状态。算法版本升级不能悄悄改写历史成绩。
- 学习会话：开始/暂停/恢复/结束、有效活动时间。保留最少必要数据，不为了统计上传完整私人聊天。

统计口径必须先于页面确定：
- “学习词数”按日去重；“复习次数”按有效提交计数，二者分开。
- 认识/模糊/忘记先按有效评价事件统计，使三者合计等于评价次数；若展示当日词汇构成，则每词取当日最后一次有效评价，单独标注，不能混用分母。
- 掌握率只使用有定义的评估事件；跳过、无作答、用过提示与超时分开，不自动记为正确或忘记。
- 有效时长只计前台有效练习，排除后台、挂屏、重复并行会话；音频连续练习需要合理计入。空闲阈值先提出假设，再用真实行为校准，避免阅读慢被误扣时间。
- 跨午夜、旅行换时区、夏令时、离线补传、删卡、撤销评分、不同设备重叠会话都要有确定规则与样例；历史日归属不随查看设备时区随意跳动。
- 提供数据解释与删除/退出路径；删除来源聊天后，学习卡保留什么快照必须让用户理解并符合账号删除语义。

工程边界沿用现有要求：App 组装导航；Feature 不跨导入；SwiftData 留在 PersistenceKit actor；服务端 PostgreSQL 为权威、Redis 可丢弃；路由→服务→仓库事务。复用同步能力但不假设既有收藏同步天然满足复习事件冲突合并。

## 10. 成本与性能约束

- 普通背词、评价、调度、统计应可确定性完成，不调用 LLM；有缓存译文直接用，否则沿用 Apple 本地翻译。
- 优先复用词典、原聊天句子、已有讲解和本地音频。别为每次翻卡重新生成例句、评分或长评语。
- 必须使用 AI 的功能先做批量/缓存/去重/按需方案，清晰标注触发时机和用户价值；取消页面不得遗留重复收费请求。
- 每批预算卡写：AI 调用数、输入/输出 token、缓存命中率、媒体流量/存储、本地模型内存和电耗，以及人均每周增量成本。基于线上实际基线设预算，未知写未知，不能凭空报“节约百分比”。
- 核心离线复习不因 AI 服务不可用而失败；性能目标按设备基线定，记录开始练习、翻卡、答题、音频开始及同步延迟。低端 iPhone、iPad 布局、动态字体和 VoiceOver 必须考虑。
- 核心训练不可被成本统计误扣模型积分；订阅权益、音视频版权与内容成本单独评审，不能悄悄新增收费承诺。

## 11. 验证：产品好用与学习有效分开证明

每批必须同时给出行为验收和效果检验方案，先测基线，再做变化。

| 维度 | 可检查的证据 | 不可替代它的指标 |
| --- | --- | --- |
| 记住 | 隔天/7 天/更长期的无提示回忆，使用保留题或等价新题 | 当场点“认识”、反复刷原题 |
| 听懂 | 隐藏文本时对新录音的理解，难度与语速可比 | 开了字幕播放过 |
| 会用 | 新情境造句/口述，预先定义评分规则并抽样人工复核 | 在原句照抄目标词 |
| 效率 | 达到相近延迟成绩所需的有效分钟数 | 单纯时长增长 |
| 体验 | 无指导完成任务、能解释按钮含义、误触/退出原因、负担反馈 | 满意度一句“挺好” |
| 可信 | 统计与事件账本核对一致、离线和多设备无重复 | 页面数字会增长 |
| 定位 | 聊天自然度、用户主动练习意愿、强制打断率 | NPC 每段都带知识点 |

先以 5–8 位不同水平用户做可用性试测，可发现流程问题，**不能据此宣称学习效果显著**。长期学习收益需要更长观察及足够样本；样本量依据目标效应和实际招募制定，不固定套用小样本。

有条件时使用随机分组或配对设计，控制学习时长、题目难度及初始水平，预先登记主要指标、期限、缺失数据处理、停止条件。排除教学/演示账号，报告流失和偏差；用户少时明确写“方向性反馈”，不编造显著性。

功能测试覆盖：评分与到期、撤销、重复提交、断网重启、异步旧结果、跨端乱序、时区、迁移、账户隔离、退出清空、媒体失效及字幕时间码。iOS 复用已有构建，按影响选择单元/集成/短路径 UI 验证，避免每轮全套测试。

## 12. 分阶段推进和停机点

| 阶段 | 交付物 | 通过条件 |
| --- | --- | --- |
| P0 基线与任务定义 | 现有能力审计、用户分层、主要学习困难、成本/指标基线 | 明确先解决哪类用户的哪一个问题 |
| P1 广泛实景调研 | 来源目录、任务截图/录屏、机制卡、反例、访问阻塞清单 | 范围覆盖、核心候选有可追溯证据，未知不伪装成事实 |
| P2 合成与小原型 | 机会排序、多个整合方案、用户任务原型、成本与权利检查 | 能说明优于现状，真实任务能完成，关键假设可验证 |
| P3 第一条学习闭环 | 小范围实现、数据定义、测试、特性开关与回退方案 | 从聊天加入到复习与统计闭环可用，数据/内容正确 |
| P4 试用与纠错 | 可用性记录、延迟测验计划/结果、成本实测、问题优先级 | 解决关键缺陷；证据不足保持试验状态 |
| P5 分批扩展 | 每批只扩展一个主要能力，发布记录与后测 | 复用有效底座，不把未经验证假设层层堆叠 |

进入新阶段先做自查并报告结论；用户启动工程后，已授权范围内的研究、可逆原型与常规实现不逐步索要确认。涉及未授权付费、邀请真实测试者、向外发送消息、发布新平台内容等才单独处理。沿用仓库已授权的后端部署规则；iOS TestFlight/App Store 分发单列，不能混称“已上线”。

**用户已启动工程。** 从 P0/P1 开始持续执行第 8 节闭环；当前未创建后台定时任务。

启动后的持续执行：一次启动指令即在其授权范围内持续运行“研究—判断—设计—实施—检查—修复—复盘—选下一批”，不把一次提交或阶段汇报当成自动停点。每轮必须满足质量、成本和复杂度门槛，未通过先修复、缩减或撤回；没有合格候选时补证或明确收束，不为了循环而制造功能。具体调度、恢复和停止规则见工作流第 8 节。调研与后续开发已获启动授权；未启用定时自动化。

执行细节见 [工作流与模板](workflow.md)；跨轮次状态见 [进度账本](status.md)。

工作流自身也接受运行监测与持续修订：异常取证、根因判断、最小规则变更、验证、生效、采用核验和后测回退，详见工作流第 9 节与 [版本账本](workflow-versions.md)。后续批次必须采用最新已验证并正式生效的规则，不能仅凭最新草案覆盖当前工作流。

## 执行账本自动检查

每批更新 [机器账本](execution-state.json)，运行 `python3 Scripts/verify-learning-program.py`；修改检查器时运行 `python3 -m unittest discover -s Scripts/tests -p 'test_learning_program_ledger.py'`。检查器核对生效版本、依赖、验收状态和证据路径，并列出可继续的任务；单个受阻任务不会阻塞无依赖的工作。证据文件存在不代表内容真实或质量合格，仍须人工/代理复核；该工具不运行账本中的命令、不启动后台循环、不代替测试及视觉检查。

# DeepSeek V4.1 Flash 学习内容能力评估

本轮按用户要求测试已有 DeepSeek 通道，正式模型标识 `deepseek-flash`，推理 `high`。旧 `deepseek-v4-flash` 已由官方映射到同一模型，本轮改变的是显式标识、推理设置和此前修复后的输出合同，不能据此归因成“新版模型优于旧版”。

## 样本和预先规定的判断标准

- 实际三角色蓝图：Oliver、Ruby、Marcus，各生成一个小学三年级单元，每单元六题，使用当前正式题库去重。记录首次结构/内容检查和独立审题结果，不靠多次重试挑选成功样本。
- 正例：已逐题编辑的 Oliver 家庭礼物单元。检查独立解答、标识和错误反例是否正确，以及是否误拒绝可成立的题目。
- 反例：在该单元中固定注入六类缺陷，预期六项全部识别：第一题多个合适答案；第二题依赖没有给出的剧情；第三题提示直接给答案；第四题混合虚拟语气超出该档；第五题所有候选句子语法错误；开场剧情直接给出组句答案。
- 首次出题的结构与标识错误、答案错误、歧义、解析错误、提示泄题或严重超纲都计为缺陷；接口成功和自行评审通过不能代替逐题核读。
- 自动审题作为质量门禁的最低要求：反例 6/6 命中，正例不误拒，独立解答和反例判分正确。本轮只是极小的定向样本，不能估计一般漏检率。
- 对无监督自动发布不作达标认证：还缺跨年级、多版本教材和足够独立样本的审核效果验证。若本轮表现稳定，也只证明可以进入受监督的候选生产，首批仍逐题编辑复核。

## 执行方式

后端 `09fa97d`，最多八次真实供应商请求，每次最多 16000 输出 token、120 秒，禁止自动重试。评估使用正式生成处理器和实际蓝图；审题只见题干、选项、提示、剧情，不见作者答案和解析。作者解析由随后逐题复核覆盖。

本轮证据目录：服务端 `/tmp/learning-eval-deepseek-09fa97d`；结果复制到本地 `build/learning-verification/deepseek-eval-09fa97d/`。不写正式题库、生成任务、用户进度或用户额度；保留全部首次失败。

## 结果

**结论：可作为需要编辑复核的候选作者和辅助审题者；当前配置未达到无人复核直接入库的要求。** 不建议仅凭它自己的审核结果自动发布。

共 8 次真实请求，全部返回 `deepseek-flash`。输入合计 50123 token，输出合计 61072 token（包含供应商计入的推理消耗），串行请求耗时约 284 秒。8 次均完成网络请求，其中 7 次有合法最终 JSON；Ruby 补充审题达到 16000 token 上限却未输出最终正文，不能计作审核成功。

| 检查 | 实际结果 |
| --- | --- |
| 新单元作者结构合同 | 3/3 通过，共 18 题 |
| 原流程进入待审 | Oliver 通过；Marcus 被审题否决；Ruby 被去重规则误拒，未进入该轮审题 |
| 编辑参考正例 | 6 题解答和错误反例判分正确，未被拒绝 |
| 预设六类明显缺陷 | 6/6 识别，报告指出了具体题目与原因 |
| 补充 Ruby 审题 | 第 8 次请求，输出预算耗尽、最终正文为空，保留失败、不再重试 |
| 直接发布 | 0 个；本轮所有候选都未加入正式题库 |

Ruby 的首次拒绝属于工程误拒：配对题题干同为“把三句话与它们在这里的交际目的配对”，但已有题材料是 Hello / Goodbye / Thank you，新题材料是 Thank you / Here you are / You're welcome。它们有局部重叠，却不是同一组题。`3dfc923` 已改为按实际两列词句去重，不依赖 ID、顺序和通用操作文案。5 项补库内容门槛测试、类型和改动 ESLint 通过，三份原始候选重新做确定性检查均通过。首次误拒结果仍保留；补充审题没有重生成或修改 Ruby 题目。

## 逐题编辑复核

| 单元 / 题目 | 复核结论 |
| --- | --- |
| Oliver / animal-cat-intro | 独立、唯一可答；同一题同时练 This/is/a 与动物词，需避免把它只统计成词汇识别掌握。 |
| Oliver / animal-word-match | 三组词义、标识和答案正确。 |
| Oliver / animal-dog-sentence | 中文限定与单词输入一致，dog 判分正确。 |
| Oliver / animal-bird-arrange | 给定词块下正确顺序明确；difficultyReason 声称“选择正确冠词”，但只给了 a，描述需要收窄。 |
| Oliver / like-dogs-choice | **提示泄露判断结构。** 提示明确“先用 I，再说 like”，而三个选项恰好在 I like / I likes / I am like 上区分；独立审题仍判 hintDoesNotReveal=true，未可靠拦住这一较隐蔽泄题。 |
| Oliver / like-cats-completion | **解析不准确。** “写成 cat 会被理解为单只的猫”不成立：在此表达中单只猫需要相应限定词，不能把裸单数直接教成单只义。正确答案 cats 本身没问题。 |
| Ruby / intro-self-ruby | I am Ruby 是预期答案；建议题干明确面对面介绍，解析不能将 This is… 在电话自我介绍等场景中的合法用法一概排除。 |
| Ruby / intro-friend-ben | 词块和正确答案一致；提示较强，仍可改为只提醒核对人物及关系。 |
| Ruby / intro-name-lily | My name is Lily 的单词输入和判分正确。 |
| Ruby / polite-pen-please | **干扰项不够确定。** “A pen, thank you.” 在适当服务/请求语境可以自然且礼貌；笼统“礼貌地要一支笔”不足以把它必然判错，解析“不能替代 please”也过于绝对。应重写任务条件或干扰项。 |
| Ruby / polite-phrases-match | 实际材料与已有题不同；三组交际功能基本对应，不应仅因通用题干相同被拒绝。 |
| Ruby / polite-book-please | 给定词块的答案可判；“只说 A book 就没有礼貌请求的语气”把礼貌完全等同于是否有 please，需改成具体语境下的学习目标。 |
| Marcus / morning-door | 题干给齐时段，答案与解析适配。 |
| Marcus / greeting-match | **开场提前给出 Hello/你好 对照。** 自动审题正确拦住剧情泄题；其同时把结尾 Goodbye 算作提前泄题不够精确，因为该幕在第六题之后，但不改变开场确有泄题的结论。 |
| Marcus / afternoon-greeting | afternoon 的单词输入和判分正确。 |
| Marcus / greet-mrs-lee | 固定词块及标点下顺序可判；解析应说明“本题给定的词块与标点”，不要泛称称呼一定放句末。 |
| Marcus / introduce-ana | 第三方介绍与 my/your 区别明确，答案正确。 |
| Marcus / my-name-ana | 基础组句和答案正确，提示较强但未额外写出完整英文答案。 |

名词用法核查参考 [Cambridge 的可数与不可数名词说明](https://dictionary.cambridge.org/uk/grammar/british-grammar/nouns-countable-and-uncountable)。这里评估的是具体题目、解释和约束，不将一处错误推广成模型完全不能教英语。

## 采用方式与下一步

保留 V4.1 Flash 高档推理作为公共候选生产配置，继续逐题编辑审核。明显缺陷检测有价值，但较隐蔽泄题、交际语境歧义和解析过度概括仍会出现；盲审本来不读取作者解析，因此作者解析必须另有编辑复核，不能把盲审通过当作解析已查。

后台管理应承接候选预览、逐题编辑、重新审题、版本绑定发布与退回，并展示失败原因、实际模型和用量。正常参考稿通过也不能代表已核实其它学段；本轮没有小学到高中全档能力证据，没有生成内容正式入库后被第二用户复用的成功记录。

证据保留于上述本地目录：`summary.json` 为原始七次流水，`fresh-ruby-review-supplement.json` 为第八次空正文结果，`deepseek-ruby-review-09fa97d.log` 保存退出结论。前三份作者稿和所有已返回审题报告均可复核。

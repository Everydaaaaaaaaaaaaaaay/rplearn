# 自然聊天、跨批作答与规则校准（2026-09-22）

起点8fe36088。工作流先采用WF-1.3，按用户提醒与实际反例在安全检查点迁移至WF-1.4。目标不是刷过上一轮95例，而是检验未选练习的自然聊天、专名、跨批作答和同日进步。

## 预先定义的输入与判断

新增28个无显式任务样本，并追加3个专名与中文谓语/理由对照，覆盖食物/学习/工作/爱好/日常计划/澄清，以及问候、感谢、表情、NPC单方面提供答案、要求翻译、引用且否认是自己答案、中文/拼音/西班牙文和中英混合。正例除完成与否，还校验预期能力是否被记录。三个专名正例：西湖、浅草寺、王老师；专名原文不应让完整英文失效。样本是人工编写，不读取用户私人聊天。

另用实际ChatViewModel、正常模型与打字节奏，在隔离存储中执行：问候→回顾→只表达选择→回顾→补充理由→回顾。与同批分两条消息不同，此案例在前半句被消费后才继续。

## 发现与修复

1. 自然聊天首轮28例，专名选择被判不完整，专名经历被协议校验拒绝。增加逐条依据的专名标注与英文句法框架校验；不能把中文理由或整句中文伪装成专名。第二轮捕获names层级错误及遗漏，进一步统一schema与输出示例；错误输出保留，没有自动改写分数。
2. 实机分批作答复现失败：answer-completes-task、independent-evidence-recorded均失败。未结束任务保留已观察且仍存在的有限原文上下文，最多8条/4000字符；新输入才触发回顾，不因保留上下文自动循环收费。合并原文按ID去重，删除原消息后排除，辅助标记跨批保留，任务结束时清除。证据采用引用消息的完整原文与顺序，避免同一个截取短语掩盖新补充的内容。
3. 确定性反例证明：同日首个未完成表达会占住唯一证据槽，隐藏随后独立完成。调整为每天优先有效完成，再恢复时间顺序；每日最多一份、重复来源限制、辅助排除和删除墓碑保留。这是证据选取规则的修正，不是证明每日一份最优。

## 规则版本与数据

存储格式version仍为1；新增可选ruleRevision，旧记录缺省可解码，加载后采用revision2。原始证据、分数、奖励和已处理批次不修改；展示状态按新选取规则重算，不清库、不补发经验。旧档采用规则的往返测试检查证据、奖励、批次集合完全一致。

## 校准而非固化数字

每轮比较现行规则、最小替代和不修改。此次有可复现证据支持改变选取顺序，没有证据支持擅自缩短7/14日、降低5/6门槛或改变每日预算，因此这些仍保持待验证假设。模拟能揭示路径和偏差，不能替代真人纵向难度与学习效度校准。下一相关批次检查低频/高频、先错后对、跨日恢复及辅助使用的差异，而非只看总体通过率。

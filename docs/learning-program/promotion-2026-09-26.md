# 全局水平进阶实现与验收

日期：2026-09-26。本页记录 P3 的进阶事务与原生流程，不代表全年级课程已完成。

## 行为

- 英语旅程展示当前档位的九星点数、学习主题覆盖、综合迁移单元及下一档题库条件。具体课程标准随经过审核的课程发布，不能从几个样板自动推导。
- 达标后开启独立的进阶短章；服务端保存剧情版本与阅读位置，退出后可以继续。逐页确认只证明客户端提交了推进操作，不证明用户实际阅读或掌握。
- 读完短章后仍需明确确认才更新既有用户档案。学习事务、档案版本更新和同步事件一起提交；失败全部回滚。客户端同步最新档案后返回英语旅程。
- 不同角色贡献同一档全局点数。主题覆盖按不同单元与题目计数，同一单元被不同角色再次完成不能重复充当主题证据。
- 旧挑战的内容与计分档位冻结。升级后补完旧题仍计入旧档，新开启的挑战读取更新后的档位。升级本身不发放点数或星星。
- 手动切换继续复用既有强提醒。与进阶并发时按档案版本决定唯一成功操作；重复完成既有进阶不能覆盖用户后来手选的档位。
- 用户数据导出包含其进阶记录；删除用户按外键级联清理，不触碰其他用户。

## 配置与边界

`Backend/config/learning/promotions.json` 是经过审核的课程验收清单，与题库分开发布。每档需要主题目标、迁移题的准确版本和内容指纹、下一档角色供给、原创进阶剧情、来源及审核说明。启动时核验来源、目标所属档位和迁移题指纹。

当前清单为空：正式内容仍只有三位主角色的小学三年级样例，尚不足以宣称覆盖完整学年。因此线上会明确显示“本级完整课程与进阶标准尚在准备”，不会仅凭样例题开放升级。补齐正式课程清单、迁移单元、下一档供给和目标导向抽题仍是后续必需工作。

新表 `app.learning_promotions` 由迁移 0038 创建；原有迁移、档案、聊天和学习奖励保持。唯一约束保证每位用户每档至多一个活动或已完成的进阶。课程修订会替代尚未完成的旧短章，保留旧记录。

## 验证范围

- 隔离 PostgreSQL 中通过真实判题完成 90 个工程单元，验证两角色合计 540 点、主题与迁移门槛、剧情续读、身份隔离、重复推进、显式确认、并发完成、手动切换竞争、同步事件唯一、故障回滚、旧挑战冻结、新挑战变档和账号导出。工程夹具不进入正式题库。
- 原生测试使用 Debug 进程内预览，不写账号、不调用模型；验证续读、取消与确认、返回后显示新档。真实账号的原生升级整链路仍需正式课程可用后验证。
- 正式课程的教学效度、教师审校和长期学习效果未由这些工程测试证明。

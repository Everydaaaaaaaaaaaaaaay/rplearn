# 语境复习：数据与同步设计决策

2026-09-16，WF-1.2。状态：设计审计完成，尚无生产表、接口或排程上线。

## 代码证据与边界

已读 `Backend/src/modules/content/{schema,repository,service}.ts`、`Backend/src/infrastructure/sync-change-writer.ts`、`Packages/LingoKit/Sources/SyncKit/BackendContentSyncCoordinator.swift`。

现有 content_records 是账号隔离、带版本的可变资源；命令通过账号+commandID 查收据并校验请求哈希，同事务写资源与同步变化。它适合收藏快照，不能直接冒充不可变练习事件。特别是 iOS 把未知 content resourceType 解码为 invalidResponse：直接向老客户端投放新的 content.learning 类型可能阻断原收藏同步。此为代码层兼容风险，尚未在线触发或测试。

决定：复习使用独立学习模块和版本化端点/游标，不扩展现有 content 枚举或把事件塞进 favorite payload。可复用认证、命令收据的设计与数据库连接；首版独立学习游标，避免要求老 App 理解新事件。实际实现前核对路由及账号删除装配；不修改历史迁移。

## 最小模型

| 对象 | 关键字段和约束 |
| --- | --- |
| 学习项 | userID + itemID；用户显式加入；词形、语言、义项标识；active/paused/removed；绑定当前 materialVersion |
| 材料版本 | userID + itemID + version；不可变释义、可选原句/已有译文、来源类型和引用；仅保存必要单句，不上传整段聊天；音频引用可失效，不作为答案唯一载体 |
| 练习尝试 | attemptID、itemID、materialVersion、sessionID、模式；题目揭示前建立；hintUsed/answerExposed 为只增事实；同次撤销重评继续同 attemptID |
| 学习事件 | userID + eventID 唯一；kind、attemptID、rating 或 targetEventID、设备序号、客户端发生时间/时区、服务端接收时间/顺序、schemaVersion；追加写，禁止更新历史评分 |
| 投影 | 用户+学习项的下一到期与统计，可由有效事件重算；记录算法和投影版本；不是事实源 |

义项不明先作为用户保存的一个材料版本，不声称自动完成词义消歧。不把两个不同来源的同拼写词粗暴合并；同时区分“材料数”和按规范化拼写去重的“词数”。材料缺可靠释义不生成客观题，先补充内容或跳过。

## 命令与冲突语义

- 相同账号、相同 eventID、相同规范化请求返回原收据；同 ID 不同内容返回冲突，绝不覆盖。JSON 哈希采用固定字段的规范化 DTO，避免键序不同导致伪冲突。
- 先写材料与加入事件，再写其尝试；离线批次按依赖上传。缺少依赖返回可重试的明确错误，不能悄悄丢弃。
- 事务锁用户/学习项后分配服务端序号并写事件及投影；同一尝试重传不会加次数。服务端序号是合并顺序，客户端时间只用于保留当时学习日和诊断，不让回拨时钟回滚排程。
- 同项跨设备同时练习保留各自 attemptID；真实尝试数可为 2，唯一词数为 1。同材料短期重复已曝光的回忆不得作为独立长期测试；首版排程采用保守合并，不因离线积累多次“记得”连续倍增间隔。具体时间窗和算法参数仍需回放验证。
- 撤销只能指向本人、同学习项的评分事件；重复撤销幂等，无效目标明确拒绝。撤销评分不删除答案暴露事实。重新评分关联原 attemptID 并替代其有效评分；不能伪装成新一次首次回忆。
- 修改释义产生新材料版本。历史评价仍绑定旧版；新版重大义项变更建立新学习项，不能继承“已掌握”。

## 统计、删除与迁移

学习日固定为事件当时的本地日期和合法时区；服务端核验日期与时间一致，异常时钟单列，不静默改变历史。每日词数按规范化词形去重，材料数单列；自评分布用每材料当日最后有效评分，不能让分布与词数混用分母。时长区间先按 UTC 去重，再按会话固定时区切日，避免多设备重叠累加。长期客观回忆指标排除同尝试重评和提示样本。

用户取消收藏不自动抹掉学习记录；移出复习停止排程；删除学习材料则清除原句快照和可识别内容，保留何种汇总需在产品说明中明确并符合账号删除规则。账号删除必须级联清除全部学习事实/快照/收据，不能只删投影。首版不默认把历史收藏转成学习项；用户主动选取时记录真正加入时间。数据库只做向前增量迁移；功能停用可以隐藏入口并停写，不删用户表回滚。

## 可执行验收样例（实现阶段）

| 场景 | 预期 |
| --- | --- |
| 上传同评分 3 次 | 1 次尝试、1 份收据结果、1 个有效评分 |
| 相同 eventID 改为别的评分 | 409；历史结果不变 |
| 忘记→撤销→记得 | 1 次尝试，最终记得；保留已看答案，不入无提示延迟样本 |
| 两个账号相同 item/eventID | 各自独立；不能查询/撤销另一账号记录 |
| 离线跨午夜后补传 | 保留原学习日；不按接收日挤在一起 |
| 两台设备重叠练同词 | 词数 1；实际尝试分别保留；时长区间不重复 |
| 删除来源消息 | 经用户明确保存的学习快照仍可用；来源跳转显示不可用 |
| 改释义 | 历史结果仍指旧内容，新版可回溯 |
| 旧版 App 同步 | 原收藏与聊天继续工作；不投放未知 content 类型 |
| 退出/切换账号 | 缓存、待上传、游标全部按账号隔离，无串号回传 |

下一步先实现独立、确定性的事件归约与统计测试，再接持久化和界面。测试必须覆盖上述语义；不得把这份设计记录视为运行通过。排程算法仍单独评估，普通复习零新增 LLM 调用。

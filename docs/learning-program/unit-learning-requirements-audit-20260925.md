# 单元学习系统与原始需求逐项核对

更新：2026-09-25。本文件记录当前代码和材料的可验证状态，不把功能可运行等同于教学质量验收。

## 数据归属与页面位置

| 原始要求 | 当前实现与判断 |
| --- | --- |
| 双方聊天按字符积累 1000 字符挑战进度 | 已接入用户与角色保存后的文本消息；服务端按账号和消息 ID 去重，进度按角色存放并封顶 1000。服务端仅收到客户端报告的字符数，尚未独立校验聊天正文与计数。 |
| 从聊天左滑进入该角色学习页 | 已实现随手指横移、松手完成或回弹；角色页仅显示该角色的挑战门槛、当前挑战和历史记录。 |
| 角色挑战互相独立，只有水平进度全局 | `unit_learning_characters` 和 `unit_learning_attempts` 按角色隔离；`unit_learning_accounts` 保存全局年级、答对数、星星对应的累计数和实际升级次数。新增账号级进度读取接口，英语旅程展示全局水平。 |
| 主线只有一份，随全局学习进阶 | 已移除三套按角色写的主线，改为一条连续的 12 章旅行册剧情；章节只由账号级 `completed_levels` 解锁，手动调整起始水平不跳章。入口位于“我的 → 英语旅程”，原有“当前英语水平”修改入口保留。 |
| 九颗星与年级进阶 | 当前每 10 道新答对题点亮一星，90 道升一级；升年级后更新档案难度，之后的聊天请求和单元按新档。返回聊天时也重新读取当前难度，避免页面内沿用旧值。 |
| 完成后重答漏题、下一轮不重复 | 服务端首轮三题均作答后完成单元并清零该角色聊天进度；已完成记录可重答未答对题。每题只在首次答对时给一次分，同角色同年级的已用模板不再抽取。 |

## 仍未满足原始质量要求的部分

1. **预设题量不足以支撑持续升级。** 当前三名主角色各年级 4 个预设、每单元 3 题；一轮年级至少需要 30 次全对挑战。一个角色的一个年级至少有 26 次挑战会依赖生成（答错时还会更多）。这不能称为“丰富的预设足够持续抽取”。必须补充经人工编写、逐题审查的内容，或重新设计经学习效果验证的进阶门槛；不能用自动生成冒充亲自编写的预设。
2. **教材证据与能力效度不足。** 教材库登记了官方目录、公开活动和少量样页，但尚未逐册核对完整课文、练习和教师说明；一、二年级与高中实际教材页尤其不完整。当前 144 个原创 v2 单元是内部试用题库，尚无教师逐题审校、首答难度统计、跨日迁移和外部能力验证。九星升级只代表应用内练习进度，不能声称实际达到相应学校年级英语水平。
3. **题型和反馈还较窄。** 当前只有单选、词块排序、精确匹配短写三种题；无听力、口语、可接受多种正确表达的写作，也没有以证据作答的长文本任务。高中阶段尤其不能由三道封闭题覆盖阅读、表达和论证能力。
4. **生成题的入库审查仍是自动化。** 服务端会按角色、年级和教材来源生成，进行格式/答案检查和第二次模型审题，公共角色通过的题进入共享库，私有角色题只对所属账号可用。但缺少人工审校、版本发布闸门和上线后的质量回收，不能保证共享库长期保持教材级质量。
5. **奖励发放时机不完全符合“完成挑战后”字面含义。** 服务端目前每道题首次答对就立即给全局进度，即使这一轮还没全部作答；已完成后补对旧错题同样立即给分。首次答对计数与防重复成立，但如果产品要求“整轮完成才结算”，需要改成完成时统一结算并处理跨年级阈值的剩余答对数。
6. **主线演绎仍是阅读型。** 已有唯一全局剧情和按升级解锁的章节，但章节目前是静态双语阅读，没有剧情系统的角色演绎、已读回执、选择与后续影响。解锁满足基础规则，叙事体验仍需深化。
7. **现有难度档位与单元年级不是完全一一对应。** 旧档位还含启蒙、大学英语与进阶；单元题库目前只有小学一年级至高中三年级。服务端把启蒙映射为小一，把大学及以上映射为高三练习，但聊天仍使用用户选择的原档位。英语旅程现已明确显示这一映射；若要真正共用一个等级概念，仍需扩充题库或重构档位。

## 验证边界

本轮用后端类型检查、隔离数据库集成测试、iOS 模拟器构建和定向 UI 测试验证数据归属、页面入口与基础导航。免登录模拟器无法替代真实账号的“聊天 → 满条 → 答题 → 升级 → 英语旅程解锁”全链路，也不能验证真实学习效果。正式开放学习系统前，应按上述质量缺口继续补齐并做实际学习者试测。

后端账号级进度接口随版本 `0070bce` 原子发布：API 与 Worker 正常，公网健康检查为 200；新接口匿名请求为 401，未知路径为 404。旧客户端没有新页面入口，也不依赖这个新增接口。iOS 改动仅安装在本地模拟器，尚未发布商店客户端。上述线上探针不等于已验证登录账号返回的实际进度或主线解锁。

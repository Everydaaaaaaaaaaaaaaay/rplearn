# 继续扩样与可选跨情境复用

## 本轮选择

当前原型已有表达、帮助、评价和经验，却缺少完成后再次使用同一种表达能力的低干扰路径。增加一个可选的隔日邀请：上次说周末去处，下次聊饮料或书，仍然在完整聊天界面表达选择和理由。

邀请放在已有完成记录内，不新增 tab、货币、每日任务、红点或通知。不把旧答案预填进新对话，也不要求背诵；查词和翻译仍可使用。是否确实改善迁移能力需要真人纵向试验，不能把点击邀请当作掌握或学习收益。

第一版“隔一个本地日可出现”是可测试的原型参数，不是个体化最优间隔。一次只出现一个建议；当天不出现、进行中的练习不出现、当天退出练习后不出现。可以选择今天不练，延期跨重启保存，不扣经验。删除来源原文后不再据此推荐，也不退回旧记录继续催促。

选择建议完全本地执行，没有模型调用。接受后复用现有聊天和评价请求，按原有参与规则计算经验；不发额外迁移奖励，不因为借助工具或延期降低等级。长期未回来不会堆积一串待办。

## 设计筛选

| 候选 | 决定 | 原因和下一步证据 |
| --- | --- | --- |
| 隔日换情境表达 | 本轮做小原型 | 补齐完成后再使用的路径；复用聊天，零推荐调用 |
| 聊天中主动澄清误解 | 保留候选 | 能练习真实沟通；先定义如何区别听不懂、故意换话题和不想回答，不能强制 NPC 制造误会 |
| 用户自己的旧表达变成可选回顾 | 暂缓 | 可能有价值，但与收藏/词典功能重叠；要先证明不是增加另一套列表 |
| 词汇/句式自动抽取并每日出题 | 暂缓 | 增加后台评价成本和误抽风险；必须先验证对真实聊天复用的增益 |
| 更多进度条、连续签到、错题债务 | 不做 | 当前缺口不是奖励数量；容易让聊天变成清任务 |
| 同一句话反复刷经验 | 不做 | 重复原句不等于跨情境使用，保留现有去重规则 |
| 自动提高 CEFR 或半年强制升一级 | 不做 | 使用频率不是能力证据，尚无长期校准数据 |

新增设计统一经过：指出现有流程缺口 → 定义能观察的收益与负担 → 最小嵌入现有流程 → 失败/退出/删除/成本测试 → 有问题就修改或撤回。不得仅以功能数量或点击率作为学习效果证据。

## 扩样

新增 40 类固定输入，使样本库从 80 扩到 120：口语转写标点缺失、重复词和自我修正、拼写、表情代替语言、西班牙语/法语理由、阿拉伯文/西里尔文专名、疲劳与停止意愿、停止后改为继续、转述和引用、中文/HTML 注入、长窗口、无上下文编号、图书与饮料的新表达。

所有预期先于模型运行。纯 ASR 转写文本不等于真机麦克风测试；模拟隔日不等于真实长期用户验证。新的界面邀请先验证可发现、可延期、能进入完整聊天、没有额外发奖，再考虑扩大目标类型。

另外增加 6 类 NPC 上下文正反例，使总库达到 126 类：选项编号、明确的 yes、NPC 给出理由而用户只说 yes、无法消歧的指代、NPC 文本注入、图书编号选择。真实练习按消息顺序匹配此前的 NPC 消息，不能把用户发送后的回复倒填成上下文；每段最多 600 字符、总计最多 1800 字符，优先保留较新消息。引用 ID 和英文证据仍只能来自用户。

## 执行与纠错记录

- 初次规则测试 28 项通过。推演发现跨天结束旧练习后可能马上出现邀请，补充实际结束日并加入回归；新增 NPC 上下文边界测试后共 30 项通过（`build/DerivedData/VerificationResults/20260922T071149Z-43921.xcresult`）。涵盖来源隔离、帮助、延期持久化、删除后不复活、旧存档、进行中/退出/自由聊天及上下文成本上限。
- 首次原生 UI 6 项中 5 通过，新邀请测试在标题断言失败。录像确认已进入饮料聊天；可见标题有自定义无障碍标签，测试查询用了可见文本。修正查询后完整邀请路径通过（`20260922T071521Z-45759.xcresult`）；前 5 项证据为 `20260922T070646Z-42793.xcresult`，没有把首次失败抹掉。
- 真实模型批次执行 56 类（46 新类 + 10 回归），56 个完成/非完成结果符合预期，57 次客户端调用。53 个明确判定，3 个 uncertain：HTML 注入、无上下文编号、无法消歧的指代。它们没有被判为完成，但不能宣传成 56 个准确的明确语义分类。逐项人工查看反馈及最后 6 条 NPC 上下文响应，未发现 NPC 理由冒充用户证据。报告：`build/verification/learning-transfer-20260922/live-expanded.json`。
- 为避免扩样本身累积大量测试数据库，后续纯语义批次直接复用 reviewer 和 ledger，报告标记 executionPath；持久化和完整聊天另由原生 UI 验证。此调整不删除已有用户或测试数据库。
- 新测试入口定向验证 8 类，8 次请求、8 个预期完成/非完成结果，歧义指代保留 uncertain；`build/verification/learning-transfer-20260922/live-service-regression.json`。最终报告脚本和架构/diff 检查通过，最新版安装到用户手机并恢复普通启动；模拟器通过 `Scripts/preview-learning.sh preview` 保留原型。
- 新邀请只在 Debug 学习原型内。它尚未证明长期记忆/迁移收益，也未扩展为生产奖励系统；后续设计仍按本文件的筛选门槛，而非以功能数量推进。

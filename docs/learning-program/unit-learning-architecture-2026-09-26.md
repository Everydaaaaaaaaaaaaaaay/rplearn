# 单元学习系统：架构与数据合同

状态：设计，尚未实现。产品规则以[实施总纲](unit-learning-plan-2026-09-26.md)为准。

## 1. 模块结构

客户端建议新增 `LearningFeature`，承载角色学习页、挑战演绎和英语旅程。App 负责把 ChatFeature 的第二页槽位与 LearningFeature 组装起来；两个 Feature 不互相导入。

| 模块 | 职责 |
| --- | --- |
| DomainKit | 纯值类型、题型合同、展示状态、进阶规则的确定性投影；不发网络请求 |
| BackendKit | 学习 API、请求幂等标识、网络错误、服务端版本解码 |
| PersistenceKit | actor 内保存已分配挑战快照、作答草稿和待同步命令；向外仅提供 Sendable DTO |
| LearningFeature | 页面、交互状态、可访问性和演绎器；不自己算最终奖励 |
| ChatFeature | 页面切换与消息终态通知；不负责出题、判题或增长全局进度 |
| PlacementFeature | 保留测评、自评和选择控件；水平保存转到统一命令 |
| App | 身份生命周期、Feature 注入、导航、全局档案刷新、主线演绎入口 |

Swift target 依赖显式登记 `Package.swift`；App 文件与资源登记 `project.yml`。样板不得堆成一个数千行 App View。

服务端重建 `modules/learning`：`routes` 做身份验证和协议校验，`service` 实现状态机，`repository` 拥有事务；`grading`、`catalog`、`progression` 保持可独立测试。生成工作走 worker 的独立任务与作者/审核适配器。

跨模块通过类型和服务接口，在 `server.ts` / `worker.ts` 注入。学习模块不直接修改其他模块私有仓库。若档案和学习进阶需共同提交，使用现有数据库事务上下文组装命令处理器，不能先加学习分再异步尝试修改档案。

## 2. 两类权威数据与不可变内容

- 服务端 PostgreSQL 权威保存角色周期、活动挑战、首次答对奖励、全局各档进度与主线解锁。
- 现有用户档案仍是当前聊天水平的唯一公开来源；学习模块保存按档进度与水平变更原因，不维护第二份可独立改动的当前难度。
- 内容仓库是题库创作来源；发布后数据库中的版本化单元是实际分配依据。Redis 仅用于调度/限流/缓存，丢失不会丢分、重发奖励或遗失生成任务。
- 初次分配冻结内容版本、等级、题目 ID、评分规则、最大分值、角色设定版本和资源哈希；库中修订不改变正在做的题。

建议持久化结构：

| 实体 | 主键/唯一约束 | 主要字段与不变量 |
| --- | --- | --- |
| 角色学习状态 | 用户+角色；同角色至多一活动首轮 | cycle_id、字符数、活动 attempt_id、revision；字符数 0…阈值 |
| 消息计数事件 | 用户+逻辑消息 ID | 角色、周期、消息版本、计数策略版本、实际字数；不可重复 |
| 水平进度 | 用户+level_key | 已奖点数、各主题完成情况、规则版本；所有角色共同贡献 |
| 单元身份 | unit_id | 稳定角色键、档位、目标、场景、来源、生命周期；版本变化不生成新身份 |
| 单元版本 | unit_id+version | 公开题干/资产与私有答案/解释、题型版本、参考来源、审核记录 |
| 尝试 | attempt_id | 用户、角色、cycle_id、冻结版本、水平、状态、首轮完成时间 |
| 题目作答事件 | 用户+request_id | attempt/question/round、答案、判定、提示状态；追加，不覆盖历史 |
| 题目奖励 | 用户+attempt+question | 首次答对产生一次，指向水平档、分值、事件；事务唯一约束 |
| 用户已抽单元 | 用户+角色+unit_id | 抽取时间；跨版本和档位切换仍不重复 |
| 星星/等级完成事件 | 用户+level_key+里程碑 | 首次达标唯一；全局主线消费这些事件，不消费手动难度修改 |
| 主线进度/解锁 | 用户+chapter_id | 解锁来源、条件版本、完成状态；完成后不回锁 |
| 生成任务 | 角色蓝图+档位+课程目标+槽位 | 状态、次数、预算、候选单元、租约/超时；去重与故障恢复 |
| 业务发件箱 | event_id | 持久化后可靠分发，投影消费幂等；不是仅放 Redis 的队列 |

全部学习表以用户外键保证账号删除语义；公共题库没有用户私人聊天快照。客户端退出账号时清除账号内存状态和缓存引用，禁止把 A 账号草稿显示给 B 账号。

## 3. 角色周期状态机

`积累中 → 已满待开启 → 备题中（必要时）→ 首轮进行中 → 首轮已结束 → 新周期积累中`。

“待补答/已全对”属于历史尝试维度，与角色周期正交。否则用户有一道错题就永远不能开下一单元。

- 开始：锁定角色状态，验证满条、身份和内容可用；若已有活动尝试返回原尝试；分配未抽单元并冻结快照。
- 备题中：没有合格单元时只创建去重任务，保留 1000 字符；不先创建空挑战，更不能先归零。
- 首轮结束：所有题已作答/跳过后，在事务里完成尝试、清活动指针、旋转 cycle_id、字符归零。重复结束返回同结果。
- 并发锁顺序统一：账号学习锁→角色锁→尝试锁→题目奖励。所有相关命令遵守同序，避免跨角色答题与全局升级死锁。
- 中途取消/闪退：继续当前尝试；用户明确零分结束时走同一结束事务，不提供静默换题捷径。

## 4. 计数事件来源与可信性

当前存在消息内容同步入口，但不能把任意客户端上报的 `count: 1000` 当成真实聊天。

实施方案：

1. 复用成功消息提交链路，明确用户、会话、角色及逻辑消息 ID。初次有效持久化产生计数候选事件；导入旧记录和再次同步不计。
2. 服务端从通过校验的正文计算字符数，不接受客户端总数。助手回复应关联服务端完成请求/最终响应记录；重新生成属于同一回复槽位，不重复计数。
3. 给通用 AI 请求补充受验证的聊天关联元数据；只有真正聊天 task 可产出学习计数收据。翻译、作者生成、主动问候和剧情均无计数权。
4. 网络流式终止不能按最后一个 chunk 长度结算。选择“已完成且已提交的最终回复”为计数时机；消息持久化与计数事件通过事务发件箱连接。
5. 离线用户消息保存命令和周期标识，恢复联网后去重提交。服务端使用已签发/记录的周期关联验证归属；旧周期迟到消息记账但不进入当前条，不相信设备时钟决定周期。
6. 只有模型生成结果但客户端未成功提交的消息不得提前加数；反之消息已成功保存而事件分发失败，由发件箱重放修复。
7. Swift/TypeScript 共用 Unicode 测试向量：ASCII、中文、空白、换行、组合重音、家庭表情、旗帜、零宽连接字符。规则变更只作用未来周期。

首阶段既不追溯旧聊天，也不为反作弊上传更多完整聊天副本。长期恶意刷字符只影响获得练习机会；真正进度仍由独立判题控制。

## 5. 判题与奖励事务

一次提交必须原子完成：

1. 校验身份、attempt 所有权、题目存在、内容版本、round 和本轮可回答状态。
2. 按冻结评分配置规范化答案。忽略大小写/标点只能逐题明确配置；拼写题不能默认模糊匹配；使用稳定选项 ID，不能用屏幕位置判分。
3. 保存本轮作答事件；结果正确且尚无该题奖励时插入奖励；已存在则返回已获奖励信息。
4. 奖励投影到冻结的 level_key，重算星数与覆盖目标，仅新增合法里程碑事件。
5. 更新 attempt/revision 和持久化通知；提交后向客户端返回得分差额及最新快照。

一次首次答对只发一次分：数据库唯一约束是最终保障，UI 禁用按钮和 Redis 锁都不能替代。

同一道题的内容勘误：撤下问题版本，受影响未完成题使用人工审核的替代题/无惩罚补偿策略；保留已发成绩并记录补偿事件，不能静默修改答案让历史用户“从对变错”。补偿上限、来源与规则版本可审计。

## 6. API 草案

以下为新协议，不兼容旧 `/v1/learning/state` 整包同步。

| 方法与路径 | 语义 |
| --- | --- |
| `GET /v1/learning/journey` | 当前档位、各档摘要、九星/覆盖、主线条件、全局 revision |
| `GET /v1/learning/characters/:id` | 角色周期、字符条、活动尝试、可用内容状态 |
| `GET /v1/learning/characters/:id/history?cursor=…` | 该角色分页记录，可筛待补答 |
| `POST /v1/learning/characters/:id/attempts` | 幂等开始；返回已有尝试或新尝试；备题返回 202 与任务状态 |
| `GET /v1/learning/attempts/:id` | 冻结公开内容、当前 round、可恢复状态 |
| `POST /v1/learning/attempts/:id/answers` | 提交 question_id、round_id、答案、request_id、预期 revision |
| `POST /v1/learning/attempts/:id/finish` | 完成首轮并开始新角色周期；不要求全对 |
| `POST /v1/learning/attempts/:id/retries` | 创建补答轮，只含尚未获分题；返回同一 pending 轮以免刷请求 |
| `POST /v1/learning/level-changes` | 保存强提醒后确认的档位修改，复用共享档案合同 |
| `POST /v1/learning/promotions/:id/complete` | 校验成长和进阶剧情状态，幂等完成晋级 |

每个写命令含幂等 ID；同 ID 不同 payload 返回冲突，同 ID 同 payload 返回原结果。版本冲突 409 返回可恢复快照。错误按“仍在备题/断网可重试/版本冲突/内容撤下/无权限”区分，不能统称失败让用户重新开始。

公开挑战响应不下发未作答题的答案或完整解析；服务端判题后仅返回该题可展示反馈。评分 API 按作答轮约束并限流，不能作为任意答案枚举器。

## 7. 离线和故障策略

首版在线开始与权威判题，离线可看缓存记录、恢复场景和保存当前答案草稿；不在本地猜测发奖，也不因为断线抹掉作答。等待判题时保留当前题，重连用同幂等 ID 重试。完整离线批量判题不是本轮必须新增的系统。

音频/插图在开始前检查并预取，资源失败给明确重试或跳过入口。生成不能阻塞 HTTP 长请求；worker 租约到期可恢复，但一个题库槽位只发布一次。客户端离开页面不取消共享生成任务，也不重复创建任务。

## 8. 旧系统删除，不做兼容迁移

用户已授权完整删除旧学习数据。P1 先做明确依赖清单，然后一并删除：

- 旧 `ConversationLearningSystem`、Dashboard、Accessory、Prototype、评价/观察样例与专用 Debug 入口。
- 旧聊天情境小测 `DomainKit/Conversation/QuizService.swift` 及其触发/奖励入口、旧 `App/Debug/ReviewPilotView.swift`、专用听力素材与仅供旧训练使用的记录。先查真实引用，保留共享查词、收藏和水平测评，避免遗漏一套仍在后台出题的旧路径。
- 仅服务旧系统的 DomainKit 类型、回调、测试、评估脚本和调度；共享查词、翻译、关系点评、测评与收藏不以名字含 learning 就删除。
- 旧学习同步路由/服务/仓库、`learning_states` 和 `unit_learning_*` 原型表及记录；旧学习专属 AI route、计费任务映射和后台作者任务。
- 本地旧学习 JSON/缓存按明确目录和账号范围移除；不清 App Application Support 总目录，也不删除共享 SwiftData 数据库。

数据库已经执行过的迁移编号不重写，以一条新迁移按外键顺序删除旧学习表，再建立新表。保留历史 SQL 编号只是维护共享数据库迁移账本的一致性，不做旧学习数据转换、双写、旧 API 适配或双系统运行。

新安装需要能顺序跑完全部迁移；已有环境需要能从已执行版本直接跑到新结构。0032/0033 已按此边界执行清理，实际发布证据见实施验证记录。

现有剧情完成数据不属于被删除学习系统；保留其事实记录，无需为未发布学习原型建立复杂迁移层。

## 9. 验证与运维

- 单测：角色周期、字素计数、评分规则、奖励唯一性、旧档补答、星星边界、内容去重与版本冻结。
- 隔离 PostgreSQL 集成测试：双设备开题/提交/结束并发，事务中断回滚，发件箱重放，账号删除，内容撤下，新安装与升级。
- API：认证与越权、未知题/题型、幂等重试、数据大小限制、未授权答案泄露、生成失败保留机会。
- 客户端：定向 Xcode 宿主测试和真实模拟器交互，不在 Swift 包目录执行 `swift build`。
- 真实闭环：普通聊天→满条→独立挑战→部分得分→首轮结束→继续积累→补答→全局星星→主线→新难度聊天。测试账号与公共用户数据隔离。
- 指标：计数事件延迟、开题耗时、判题耗时、冲突/重试、重复奖励拦截、题池剩余、生成成本/质量通过率、错题率与补答率。日志只记录关联 ID/分类，不记录私人聊天或未公开答案。
- 发布：功能开关分离学习读写、生成发布、自动进阶。支持撤下有问题内容和关闭新分配；保留已获新学习成绩。数据库清理不通过回滚应用程序去“恢复旧学习系统”。

完成证据必须包含实际后端注册、迁移执行、客户端请求、真实账号结算与恢复。仅模型测试/页面预览不能标记全链路完成。

## 10. 可信聊天合同落地

0034 增加 `learning_chat_outbox`、`learning_chat_turns`、`learning_chat_operations`。内容仓库在消息首次保存事务内调用组装层注入的观察器；观察器只追加候选，不拿学习账号锁。处理器另开事务，统一先拿学习账号锁，再校验角色、模型指纹和写计数，避免内容锁与学习锁反序。

- 用户消息首次同步 payload 包含 `learningOrigin: {source: "user", cycleId}`。周期由角色状态接口签发并在客户端随消息保存；没有此字段的历史同步、剧情、主动消息不产生候选。编辑、再次同步和后加字段不补发候选。用户消息上的回复等待标记不影响正文计数。
- AI `conversation` 文本请求可附 `learningChat: {conversationId, userMessageId, cycleId}`，同时必须有 operationId。服务器核对已持久化用户消息、首次保存候选、原始正文指纹、角色归属和已签发周期，再绑定模型请求；其他 task 不可使用。
- 服务端只为完整完成的模型结果保存正文指纹；错误、未结束流和空正文不生成完成证据。普通和流式缓存重放都可补写曾失败的完成证据，且不会再次调用模型。
- 助手每个最终气泡首次保存时包含 `learningOrigin: {source: "assistant", cycleId, userMessageId, operationId, fragmentIndex, fragmentCount}`。分片索引从 0 开始，最多 8 个，全部片段依次去空白后必须与服务端完整输出指纹一致。单个片段或伪造替代文本不能获计数。
- 同一用户消息绑定永久的 `reply_event_id`；重生成可有多个模型 operation，但只有这一个逻辑回复位置能计数。历史补传仍使用原周期，不按设备时钟改派当前周期。
- Worker 每 5 秒处理候选；角色页、旅程和开始挑战查询前也尝试处理。未齐片段轮转检查，不阻塞后面的消息。已处理正文立刻清除，未齐或无证据候选 7 天后清除正文并标记过期；其余只保留关联和指纹。
- iOS 仍需接入此合同；目前不可将服务端隔离测试标为客户端聊天端到端完成。质量重试采用的最终模型 operation 必须随最终气泡保存；本地兜底文本不冒充服务端生成结果。
